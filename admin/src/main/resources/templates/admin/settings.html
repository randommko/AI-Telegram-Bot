Как добавить ключ провайдера

Ключ приходит из переменной окружения BOT_AI_KEY_<ID>. Ни один ключ не обязателен: без него поставщик виден в списке моделей с пометкой, но выбрать его модель нельзя.

Постоянный путь — секрет репозитория. Деплой на каждом пуше заново собирает /etc/telegram-bot/bot.env из секретов, поэтому строка, вписанная в файл руками, живёт только до следующего деплоя.

  1. Создать ключ в кабинете поставщика — ссылка в таблице ниже.
  2. GitHub → Settings → Secrets and variables → Actions → New repository secret. Имя секрета — латиницей, например VENICE_API_KEY.
  3. Убедиться, что в блоке bot.env файла .github/workflows/deploy.yml есть строка BOT_AI_KEY_VENICE=${{ secrets.VENICE_API_KEY }}; для поставщиков из таблицы они уже есть.
  4. Пуш в main: деплой пересоберёт bot.env и перезапустит бота.

Временно, без пуша — пока секрет не заведён:

ssh root@45.141.103.51
cp /etc/telegram-bot/bot.env /etc/telegram-bot/bot.env.bak-$(date +%F)
nano /etc/telegram-bot/bot.env      # добавить, например: BOT_AI_KEY_VENICE=sk-...
systemctl restart telegram-bot
journalctl -u telegram-bot -n 30 --no-pager

Вписанная руками строка исчезнет после следующего деплоя. Ключ не коммитить в репозиторий — он публичный; ключи живут только в GitHub Secrets и в bot.env на сервере.
