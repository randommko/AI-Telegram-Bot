# runtime-configuration Specification

## Purpose

Определяет, как Telegram-бот получает конфигурацию при запуске и подключается к внешним сервисам — Telegram Bot API и PostgreSQL — с воспроизводимой схемой базы данных.

## Requirements

### Requirement: Подключение к Telegram Bot API через конфигурируемый прокси

Система SHALL подключаться к Telegram Bot API напрямую либо через HTTP- или SOCKS5-прокси, заданный переменными окружения `BOT_PROXY_TYPE`, `BOT_PROXY_HOST`, `BOT_PROXY_PORT`, `BOT_PROXY_USER`, `BOT_PROXY_PASS`. Прокси опционален: без него используется прямое подключение, в том числе через системный VPN.

#### Scenario: Прямое подключение без прокси

- **WHEN** переменная `BOT_PROXY_HOST` не задана
- **THEN** бот подключается к Telegram API напрямую (в том числе через системный VPN)

#### Scenario: Подключение через HTTP-прокси

- **WHEN** `BOT_PROXY_TYPE=HTTP` и заданы `BOT_PROXY_HOST` и `BOT_PROXY_PORT`
- **THEN** бот направляет запросы к Telegram API через HTTP-прокси

#### Scenario: Подключение через SOCKS5-прокси

- **WHEN** `BOT_PROXY_TYPE=SOCKS5` и заданы `BOT_PROXY_HOST` и `BOT_PROXY_PORT`
- **THEN** бот направляет запросы к Telegram API через SOCKS5-прокси

#### Scenario: Прокси с аутентификацией

- **WHEN** заданы `BOT_PROXY_USER` и `BOT_PROXY_PASS`
- **THEN** при подключении к прокси используется аутентификация

### Requirement: Подключение к PostgreSQL через пул соединений

Система SHALL подключаться к указанной базе данных PostgreSQL и поддерживать пул соединений для выполнения запросов.

#### Scenario: Успешное подключение к базе данных

- **WHEN** приложение запускается с корректными параметрами подключения к PostgreSQL
- **THEN** пул соединений инициализируется, и бот выполняет запросы к базе данных

#### Scenario: Недоступная база данных

- **WHEN** база данных недоступна по указанному URL
- **THEN** приложение логирует ошибку подключения и не начинает обработку сообщений

### Requirement: Воспроизводимая схема через SQL-миграции

Система SHALL предоставлять идемпотентные SQL-миграции, которые создают все необходимые таблицы и наполняют таблицу настроек начальными значениями.

#### Scenario: Накат миграций на чистую базу данных

- **WHEN** миграции применяются к пустой базе данных через `psql`
- **THEN** создаются все таблицы и seed-данные, и бот может работать без ошибок

#### Scenario: Повторный накат миграций

- **WHEN** миграции применяются повторно к уже созданной схеме
- **THEN** выполнение не вызывает ошибок и не дублирует существующие данные

### Requirement: Запуск с конфигурацией из переменных окружения

Система SHALL получать конфигурацию запуска (токен бота, URL базы данных, пользователь БД, пароль БД) из переменных окружения `BOT_TOKEN`, `BOT_DB_URL`, `BOT_DB_USER`, `BOT_DB_PASSWORD`, ключи провайдеров ИИ — из отдельных переменных `BOT_AI_KEY_<ID>`, а пароль и адрес веб-админки — из `BOT_ADMIN_PASSWORD`, `BOT_ADMIN_PORT`, `BOT_ADMIN_BIND`, и MUST NOT требовать файл конфигурации или позиционные аргументы командной строки.

#### Scenario: Запуск с полным набором переменных окружения

- **WHEN** приложение запускается, когда заданы `BOT_TOKEN`, `BOT_DB_URL`, `BOT_DB_USER`, `BOT_DB_PASSWORD` и ключ провайдера `BOT_AI_KEY_DEEPSEEK`
- **THEN** приложение использует переданные значения и запускает бота

#### Scenario: Отсутствует обязательная переменная

- **WHEN** приложение запускается, когда одна из переменных `BOT_TOKEN`, `BOT_DB_URL`, `BOT_DB_USER`, `BOT_DB_PASSWORD` не задана или пуста
- **THEN** приложение завершается с ненулевым кодом и сообщением, называющим переменную, не пытаясь подключиться к базе данных или Telegram

#### Scenario: Конфигурация передана аргументами командной строки

- **WHEN** приложение запускается с позиционными аргументами `token dbUrl dbUser dbPassword`
- **THEN** эти аргументы не используются как конфигурация, а запуск завершается с ошибкой обязательных переменных окружения

#### Scenario: Переменные админки не заданы

- **WHEN** приложение запускается без `BOT_ADMIN_PASSWORD`, `BOT_ADMIN_PORT` и `BOT_ADMIN_BIND`
- **THEN** бот запускается и работает как обычно, админка недоступна, а пустые необязательные переменные не считаются ошибкой конфигурации

#### Scenario: Ключа ИИ нет ни у одного провайдера

- **WHEN** приложение запускается без единой переменной `BOT_AI_KEY_<ID>`
- **THEN** приложение запускается, пишет в лог ошибку об отсутствии ключа у выбранной модели и обрабатывает сообщения, не требующие модели

### Requirement: Проверка конфигурации до подключения к внешним сервисам

Система SHALL проверять значения конфигурации запуска до подключения к PostgreSQL и Telegram Bot API и MUST NOT начинать обработку сообщений при невалидных значениях.

#### Scenario: Некорректный порт прокси при заданном хосте

- **WHEN** `BOT_PROXY_HOST` задан, а `BOT_PROXY_PORT` пуст, не является числом или выходит за диапазон 1..65535
- **THEN** запуск прерывается с ошибкой, называющей переменную, и прокси не отключается молча

#### Scenario: Пустые необязательные переменные прокси

- **WHEN** переменные `BOT_PROXY_*` присутствуют в окружении, но имеют пустые значения, а `BOT_PROXY_HOST` пуст
- **THEN** запуск проходит успешно, и бот подключается к Telegram API напрямую

### Requirement: Параметры модели и лимитов читаются на каждый запрос

Система SHALL читать модель, температуру ответа, лимит токенов, размер истории и размер блока памяти из `bot_settings` при каждом запросе к модели и MUST NOT удерживать их в памяти процесса между запросами.

#### Scenario: Смена модели

- **WHEN** значение `aiModel` изменено, а бот не перезапускался
- **THEN** следующий запрос к модели уходит с новой моделью

#### Scenario: Смена температуры и лимита токенов

- **WHEN** изменены `aiAnswerTemperature` или `maxTokensQuestion`
- **THEN** следующий запрос к модели использует новые значения

#### Scenario: Некорректное значение в хранилище

- **WHEN** в `bot_settings` оказалось нечисловое значение температуры или лимита токенов
- **THEN** бот использует безопасное значение по умолчанию, пишет предупреждение в лог и продолжает отвечать

#### Scenario: Уведомление о запуске показывает модель из настроек

- **WHEN** бот стартует и отправляет уведомление о запуске
- **THEN** в уведомлении указана модель из `aiModel`, а не зашитая в код
