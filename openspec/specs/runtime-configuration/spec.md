# runtime-configuration Specification

## Purpose

Определяет, как Telegram-бот получает конфигурацию при запуске и подключается к внешним сервисам — Telegram Bot API и PostgreSQL — с воспроизводимой схемой базы данных.

## Requirements

### Requirement: Запуск с конфигурацией из аргументов командной строки

Система SHALL получать конфигурацию запуска (токен бота, URL базы данных, пользователь БД, пароль БД, ключ ИИ-API) из аргументов командной строки в фиксированном порядке и MUST NOT требовать файл конфигурации.

#### Scenario: Запуск с полным набором аргументов

- **WHEN** приложение запускается с пятью аргументами `token dbUrl dbUser dbPassword aiKey`
- **THEN** приложение использует переданные значения и запускает бота

#### Scenario: Отсутствует обязательный аргумент

- **WHEN** приложение запускается без одного из обязательных аргументов или с пустым значением
- **THEN** приложение завершается с ненулевым кодом и понятным сообщением об ошибке, не пытаясь подключиться

### Requirement: Подключение к Telegram Bot API через конфигурируемый прокси

Система SHALL подключаться к Telegram Bot API напрямую либо через HTTP- или SOCKS5-прокси, заданный переменными окружения `BOT_PROXY_TYPE`, `BOT_PROXY_HOST`, `BOT_PROXY_PORT`, `BOT_PROXY_USER`, `BOT_PROXY_PASS`. Прокси опционален: без него используется прямое подключение, в том числе через системный VPN.

#### Scenario: Прямое подключение без прокси

- **WHEN** переменная `BOT_PROXY_HOST` не задана
- **THEN** бот подключается к Telegram API напрямую (в том числе через системный VPN)

#### Scenario: Подключение через HTTP-прокси

- **WHEN** `BOT_PROXY_TYPE=HTTP` и заданы `BOT_PROXY_HOST` и `BOT_PROXY_PORT`
- **THEN** бот направляет запросы к Telegram API через HTTP-прокси

#### Scenario: Подключение через SOCKS5-прокси

- **WHEN** `BOT_PROXY_TYPE=SOCKS5` и заданы `BOT_PROXY_HOST` и `BOT_PROXY_PORT`
- **THEN** бот направляет запросы к Telegram API через SOCKS5-прокси

#### Scenario: Прокси с аутентификацией

- **WHEN** заданы `BOT_PROXY_USER` и `BOT_PROXY_PASS`
- **THEN** при подключении к прокси используется аутентификация

### Requirement: Подключение к PostgreSQL через пул соединений

Система SHALL подключаться к указанной базе данных PostgreSQL и поддерживать пул соединений для выполнения запросов.

#### Scenario: Успешное подключение к базе данных

- **WHEN** приложение запускается с корректными параметрами подключения к PostgreSQL
- **THEN** пул соединений инициализируется, и бот выполняет запросы к базе данных

#### Scenario: Недоступная база данных

- **WHEN** база данных недоступна по указанному URL
- **THEN** приложение логирует ошибку подключения и не начинает обработку сообщений

### Requirement: Воспроизводимая схема через SQL-миграции

Система SHALL предоставлять идемпотентные SQL-миграции, которые создают все необходимые таблицы и наполняют таблицу настроек начальными значениями.

#### Scenario: Накат миграций на чистую базу данных

- **WHEN** миграции применяются к пустой базе данных через `psql`
- **THEN** создаются все таблицы и seed-данные, и бот может работать без ошибок

#### Scenario: Повторный накат миграций

- **WHEN** миграции применяются повторно к уже созданной схеме
- **THEN** выполнение не вызывает ошибок и не дублирует существующие данные
