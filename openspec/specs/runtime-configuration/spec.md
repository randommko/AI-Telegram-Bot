# runtime-configuration Specification

## Purpose

Определяет, как Telegram-бот получает конфигурацию при запуске и подключается к внешним сервисам — Telegram Bot API и PostgreSQL — с воспроизводимой схемой базы данных.

## Requirements

### Requirement: Подключение к PostgreSQL через пул соединений

Система SHALL подключаться к одной базе PostgreSQL разными ролями: AI-бот — `ai_user`, админка — `admin_user`, а каждая роль MUST иметь доступ только к своим схемам и к общей схеме `shared`.

#### Scenario: Успешное подключение к базе данных

- **WHEN** приложение запускается с корректными параметрами подключения и своей ролью
- **THEN** пул соединений инициализируется, и приложение выполняет запросы к разрешённым схемам

#### Scenario: Обращение к чужой схеме

- **WHEN** AI-бот пытается прочитать таблицу из схемы `fun`
- **THEN** база отклоняет запрос с ошибкой прав, и бот не получает данные

#### Scenario: Недоступная база данных

- **WHEN** база данных недоступна по указанному URL
- **THEN** приложение логирует ошибку подключения и не начинает обработку сообщений

### Requirement: Воспроизводимая схема через SQL-миграции

Система SHALL предоставлять идемпотентные SQL-миграции, которые создают схемы `shared`, `config`, `ai` и `configurator` и все таблицы этих схем. DDL общей схемы `shared` и разовый перенос данных MUST храниться отдельным набором скриптов вне репозитория и MUST NOT выполняться при обычном накате миграций приложения.

#### Scenario: Накат миграций на чистую базу данных

- **WHEN** скрипты `shared` и миграции приложения применяются к пустой базе данных через `psql`
- **THEN** создаются все схемы, таблицы и seed-данные, и приложения работают без ошибок

#### Scenario: Повторный накат миграций

- **WHEN** миграции применяются повторно к уже созданной схеме
- **THEN** выполнение не вызывает ошибок и не дублирует существующие данные

#### Scenario: Перенос данных из public

- **WHEN** выполняется разовый перенос таблиц из `public` в новые схемы
- **THEN** количество строк в каждой таблице совпадает с дампом до переноса, а в `public` не остаётся прикладных таблиц

### Requirement: Запуск с конфигурацией из переменных окружения

Система SHALL получать конфигурацию каждого приложения из его собственных переменных окружения. AI-бот MUST получать `BOT_TOKEN`, `BOT_DB_*` и ключи `BOT_AI_KEY_<ID>`; MAY получать `BOT_ADMIN_PASSWORD`, `BOT_ADMIN_PORT`, `BOT_ADMIN_BIND`, `BOT_SSH_USER` и `BOT_SSH_HOST` для уведомления о запуске. Админка MUST получать `BOT_DB_*`, `BOT_ADMIN_PASSWORD`, `BOT_ADMIN_PORT` и `BOT_ADMIN_BIND` и MUST NOT получать ни ключи провайдеров, ни `BOT_TOKEN`. Оба приложения MUST NOT требовать файл конфигурации или позиционные аргументы командной строки.

#### Scenario: Запуск с полным набором переменных окружения

- **WHEN** AI-бот запускается с `BOT_TOKEN`, `BOT_DB_*` и ключом `BOT_AI_KEY_DEEPSEEK`
- **THEN** приложение использует переданные значения и запускает бота

#### Scenario: Запуск админки с полным набором переменных

- **WHEN** админка запускается с `BOT_DB_*` и `BOT_ADMIN_PASSWORD`
- **THEN** приложение поднимает админку, не обращаясь ни к ключам провайдеров, ни к Telegram

#### Scenario: Отсутствует обязательная переменная

- **WHEN** у приложения не задана одна из его обязательных переменных: `BOT_TOKEN` у бота или любая из `BOT_DB_URL`, `BOT_DB_USER`, `BOT_DB_PASSWORD`
- **THEN** это приложение завершается с ненулевым кодом и сообщением с именем переменной, не подключаясь к базе и Telegram

#### Scenario: Переменные админки не заданы

- **WHEN** AI-бот запускается без `BOT_ADMIN_PASSWORD`, `BOT_ADMIN_PORT` и `BOT_ADMIN_BIND`
- **THEN** бот запускается и работает как обычно, а в уведомлении о запуске нет ссылки на админку и строки туннеля

#### Scenario: Ключа ИИ нет ни у одного провайдера

- **WHEN** AI-бот запускается без единой переменной `BOT_AI_KEY_<ID>`
- **THEN** он запускается, публикует статус «ключа нет» и обрабатывает сообщения, не требующие модели

#### Scenario: Конфигурация передана аргументами командной строки

- **WHEN** приложение запускается с позиционными аргументами вместо переменных окружения
- **THEN** аргументы не используются как конфигурация, а запуск завершается с ошибкой обязательных переменных

### Requirement: Параметры модели и лимитов читаются на каждый запрос

Система SHALL читать модель, температуру ответа, лимит токенов, размер истории и размер блока памяти из `bot_settings` при каждом запросе к модели и MUST NOT удерживать их в памяти процесса между запросами.

#### Scenario: Смена модели

- **WHEN** значение `aiModel` изменено, а бот не перезапускался
- **THEN** следующий запрос к модели уходит с новой моделью

#### Scenario: Смена температуры и лимита токенов

- **WHEN** изменены `aiAnswerTemperature` или `maxTokensQuestion`
- **THEN** следующий запрос к модели использует новые значения

#### Scenario: Некорректное значение в хранилище

- **WHEN** в `bot_settings` оказалось нечисловое значение температуры или лимита токенов
- **THEN** бот использует безопасное значение по умолчанию, пишет предупреждение в лог и продолжает отвечать

#### Scenario: Уведомление о запуске показывает модель из настроек

- **WHEN** бот стартует и отправляет уведомление о запуске
- **THEN** в уведомлении указана модель из `aiModel`, а не зашитая в код

### Requirement: Изоляция схем по ролям

Система SHALL выдавать каждой роли только те права, которые нужны её приложению: `ai_user` работает со схемами `shared`, `config` и `ai`; `admin_user` — с `shared`, `config`, `ai` и `configurator`; `fun_user` — с `shared` и `fun`. Ни одна роль MUST NOT читать схемы другого приложения, кроме `shared`.

#### Scenario: Бот не читает игры

- **WHEN** роль `ai_user` выполняет запрос к таблице схемы `fun`
- **THEN** база возвращает ошибку прав доступа

#### Scenario: Админка не читает игры

- **WHEN** роль `admin_user` выполняет запрос к таблице схемы `fun`
- **THEN** база возвращает ошибку прав доступа

#### Scenario: Игры не читают конфигурацию и память

- **WHEN** роль `fun_user` выполняет запрос к таблице схем `config` или `ai`
- **THEN** база возвращает ошибку прав доступа

#### Scenario: Общие пользователи и чаты доступны всем

- **WHEN** любая из трёх ролей обновляет `shared.tg_users` или `shared.tg_chats`
- **THEN** запись сохраняется, и её видят остальные приложения

### Requirement: Уведомление о запуске содержит команду туннеля

Система SHALL добавлять в уведомление о запуске строку с командой SSH-туннеля к админке, собранную из порта админки, `BOT_SSH_USER` и `BOT_SSH_HOST`, и MUST NOT печатать эту строку, если хотя бы одна из переменных не задана.

#### Scenario: Обе переменные заданы

- **WHEN** бот запускается с `BOT_SSH_USER=deploy` и `BOT_SSH_HOST=<адрес сервера>`
- **THEN** в уведомлении есть строка `ssh -L 8081:127.0.0.1:8081 deploy@<адрес сервера>`, а порт в ней совпадает с портом в ссылке на админку

#### Scenario: Порт админки изменён

- **WHEN** задан `BOT_ADMIN_PORT=9090` и обе переменные SSH
- **THEN** и ссылка на админку, и команда туннеля используют порт 9090

#### Scenario: Переменные SSH не заданы

- **WHEN** бот запускается без `BOT_SSH_USER` и `BOT_SSH_HOST`
- **THEN** в уведомлении остаётся только ссылка на админку, без строки туннеля

#### Scenario: Задана только одна переменная

- **WHEN** задана `BOT_SSH_USER`, а `BOT_SSH_HOST` пуст или отсутствует
- **THEN** строка туннеля не печатается

#### Scenario: Админка выключена

- **WHEN** `BOT_ADMIN_PASSWORD` не задан
- **THEN** в уведомлении нет ни ссылки на админку, ни команды туннеля

### Requirement: Прямое подключение к Telegram Bot API

Система SHALL подключаться к Telegram Bot API напрямую, без прокси, и MUST NOT читать переменные `BOT_PROXY_*`. Доступность API обеспечивает сетевая конфигурация хоста: на сервере — маршруты VPN, при локальном запуске — режим TUN.

#### Scenario: Запуск с прямым подключением

- **WHEN** AI-бот запускается, а переменные `BOT_PROXY_*` не заданы
- **THEN** бот регистрируется в Telegram и получает обновления без прокси

#### Scenario: Переменные прокси остались в окружении

- **WHEN** в окружении остались `BOT_PROXY_HOST` и `BOT_PROXY_PORT` от прежней версии
- **THEN** бот их игнорирует и подключается к Telegram напрямую

### Requirement: Проверка конфигурации запуска до подключения к внешним сервисам

Система SHALL проверять значения конфигурации запуска до подключения к PostgreSQL и Telegram Bot API и MUST NOT начинать обработку сообщений при невалидных значениях.

#### Scenario: Некорректный порт админки

- **WHEN** задан `BOT_ADMIN_PORT` вне диапазона 1..65535
- **THEN** запуск прерывается ошибкой, называющей переменную, и приложение не подключается к PostgreSQL
