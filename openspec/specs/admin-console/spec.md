# admin-console Specification

## Purpose
Веб-админка внутри того же процесса: включение паролем из окружения, вход одного администратора, каркас с навигацией по разделам и доступ только через loopback.

## Requirements

### Requirement: Админка включается паролем из окружения

Система SHALL обслуживать раздел `/admin/**` только при заданной переменной `BOT_ADMIN_PASSWORD`. Если переменная пуста или отсутствует, запросы к `/admin/**` MUST получать ответ 404, а в лог MUST писаться предупреждение; работа бота при этом MUST NOT меняться.

#### Scenario: Пароль задан

- **WHEN** приложение запущено с непустым `BOT_ADMIN_PASSWORD`
- **THEN** `/admin/login` отдаёт страницу входа, а остальные разделы админки требуют аутентификации

#### Scenario: Пароль не задан

- **WHEN** приложение запущено без `BOT_ADMIN_PASSWORD`
- **THEN** любой запрос к `/admin/**` возвращает 404, в лог пишется предупреждение, бот продолжает отвечать в чатах

### Requirement: Единственный администратор входит по паролю

Система SHALL аутентифицировать одного пользователя `admin` паролем из `BOT_ADMIN_PASSWORD` через форму входа и MUST NOT пускать неаутентифицированные запросы ни в один раздел админки. Сессия MUST быть HttpOnly, а изменения MUST приниматься только с действительным CSRF-токеном.

#### Scenario: Запрос без сессии

- **WHEN** неаутентифицированный браузер открывает любой адрес `/admin/**`, кроме страницы входа
- **THEN** он перенаправляется на `/admin/login` и содержимое раздела не отдаётся

#### Scenario: Успешный вход

- **WHEN** администратор вводит верный пароль
- **THEN** открывается страница обзора `/admin`, и последующие запросы обслуживаются в этой сессии

#### Scenario: Неверный пароль

- **WHEN** администратор вводит неверный пароль
- **THEN** страница входа возвращается с сообщением об ошибке, а сессия не создаётся

#### Scenario: Изменение без CSRF-токена

- **WHEN** аутентифицированный клиент отправляет форму изменения без CSRF-токена
- **THEN** запрос отклоняется, данные не меняются

#### Scenario: Выход

- **WHEN** администратор нажимает выход
- **THEN** сессия завершается и следующий запрос к `/admin` снова требует входа

### Requirement: Админка слушает только loopback

Система SHALL по умолчанию принимать HTTP-запросы админки на `127.0.0.1` и порту из `BOT_ADMIN_PORT` (по умолчанию 8081), чтобы доступ открывался через SSH-туннель, а не из интернета.

#### Scenario: Запуск с настройками по умолчанию

- **WHEN** задан только `BOT_ADMIN_PASSWORD`
- **THEN** админка доступна на `127.0.0.1:8081` и недоступна по внешнему адресу сервера

#### Scenario: Порт изменён

- **WHEN** задан `BOT_ADMIN_PORT` со свободным портом
- **THEN** админка слушает этот порт, а бот продолжает работать в том же процессе

### Requirement: Каркас админки с навигацией по разделам

Система SHALL показывать в каждом разделе админки постоянное меню с переходами «Персоны», «Воспоминания», «Чаты», «Настройки» и MUST отдавать страницу обзора по адресу `/admin`.

#### Scenario: Обзор после входа

- **WHEN** администратор вошёл в админку
- **THEN** страница `/admin` показывает меню из четырёх разделов

#### Scenario: Переход в раздел

- **WHEN** администратор выбирает раздел в меню
- **THEN** открывается страница этого раздела, а меню остаётся доступным

### Requirement: Изменения из админки применяются без перезапуска

Система SHALL применять сохранённые в админке изменения к следующему запросу бота и MUST NOT требовать перезапуска процесса для промптов, алиасов, памяти, привязок и параметров модели.

#### Scenario: Правка промпта

- **WHEN** администратор сохранил новый промпт персоны
- **THEN** следующий ответ в привязанном чате строится по новому промпту без перезапуска

#### Scenario: Правка параметров модели

- **WHEN** администратор изменил модель или температуру
- **THEN** следующий запрос к модели использует новые значения
