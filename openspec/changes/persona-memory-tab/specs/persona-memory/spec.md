# Spec Delta

## ADDED Requirements

### Requirement: Память открывается на вкладке карточки персоны

Система SHALL показывать воспоминания персоны на вкладке «Воспоминания» её карточки и MUST позволять с этой вкладки добавить, поправить, удалить и восстановить запись. После сохранения, удаления и восстановления MUST открываться та же вкладка. Если памяти нет, вместо пустой таблицы MUST показываться подсказка.

#### Scenario: Добавление с вкладки

- **WHEN** администратор нажал «Добавить» на вкладке «Воспоминания»
- **THEN** открывается форма нового воспоминания этой персоны, а после сохранения снова видна вкладка со списком

#### Scenario: Пустая память

- **WHEN** у персоны нет ни одного воспоминания
- **THEN** вкладка показывает подсказку, что памяти пока нет, вместо пустой таблицы

#### Scenario: Возврат после правки

- **WHEN** администратор сохранил изменения воспоминания
- **THEN** открывается вкладка «Воспоминания» этой же персоны с сообщением о сохранении

#### Scenario: Возврат после удаления и восстановления

- **WHEN** администратор удалил или восстановил воспоминание
- **THEN** открывается вкладка «Воспоминания» этой же персоны

## MODIFIED Requirements

### Requirement: Воспоминания просматриваются с фильтрами

Система SHALL показывать воспоминания персоны с фильтрами по категории, связанному человеку, тексту, признаку ядра и удалённым записям, с сортировкой по важности или дате и постраничным выводом. Список MUST содержать только воспоминания персоны этой карточки; отдельного фильтра по персоне MUST NOT быть. Ядровые записи MUST быть визуально отличимы в списке.

#### Scenario: Фильтр по человеку

- **WHEN** администратор выбрал человека из участников чата
- **THEN** в списке остаются только воспоминания этой персоны, связанные с этим человеком

#### Scenario: Только ядровые

- **WHEN** администратор включил фильтр «только ядровые»
- **THEN** в списке остаются ядровые записи, каждая помечена как ядро

#### Scenario: Поиск по тексту

- **WHEN** администратор ввёл часть текста воспоминания
- **THEN** в списке остаются записи этой персоны, содержащие эту часть текста

#### Scenario: Чужая память не попадает в список

- **WHEN** в базе есть воспоминания другой персоны
- **THEN** на вкладке видны только записи персоны карточки

### Requirement: Удалённое воспоминание скрывается, но остаётся восстановимым

Система SHALL помечать воспоминание удалённым вместо физического удаления и MUST NOT показывать его в обычных списках и передавать модели; восстановление SHALL возвращать запись в список и в следующий запрос. Вернуть запись MUST быть можно из списка «удалённые» на вкладке «Воспоминания» карточки персоны, без журнала изменений.

#### Scenario: После удаления

- **WHEN** администратор удалил воспоминание
- **THEN** запись исчезает из списка и из следующего запроса к модели

#### Scenario: Анализ не видит удалённое

- **WHEN** анализ переписки ищет дубли среди воспоминаний персоны
- **THEN** удалённая запись в сравнении не участвует и не воскресает

#### Scenario: Восстановление

- **WHEN** администратор открыл список «удалённые» на вкладке и вернул запись
- **THEN** запись снова видна в списке и попадает в промпт по своим важности и дате
