# Proposal

## Why

Бот умеет работать только с одним провайдером: адрес `https://api.deepseek.com/v1/chat/completions` и ключ `BOT_AI_KEY` зашиты в единственный клиент, а список моделей — плоский список из двух значений (`deepseek-chat`, `deepseek-flash`). Чтобы ходить в другую LLM, приходится править код, а приложение вообще не стартует без ключа DeepSeek, даже если выбрана чужая модель.

Задача #77 просит переключать LLM через админку, группировать модели по поставщику и показывать, для какого поставщика нет ключа в окружении.

## What Changes

- Каталог провайдеров и моделей в коде: у провайдера — идентификатор, отображаемое имя, адрес Chat Completions, имя переменной окружения с ключом, таймаут; у модели — идентификатор, провайдер, отображаемое имя, поддержка JSON-режима, признак reasoning-модели, потолок выходных токенов.
- Пять групп провайдеров в каталоге: DeepSeek, Grok (xAI), OpenAI, Google Gemini (через режим совместимости OpenAI), Mistral. В списке показываются все группы, включая те, для которых ключа нет.
- **BREAKING** Ключи ИИ переезжают на имена `BOT_AI_KEY_<ID>` (`BOT_AI_KEY_DEEPSEEK`, `BOT_AI_KEY_GROK`, `BOT_AI_KEY_OPENAI`, `BOT_AI_KEY_GEMINI`, `BOT_AI_KEY_MISTRAL`). Прежняя `BOT_AI_KEY` удаляется из деплоя и локальных конфигураций.
- Ключ ИИ перестаёт быть обязательным при запуске: ни один ключ провайдера не требуется, чтобы приложение поднялось.
- Клиент выбирает адрес, ключ, таймаут и потолок токенов по активной модели из `bot_settings.aiModel` на каждый запрос; у выбранной модели без ключа в лог пишется ошибка, а уведомление о запуске показывает провайдера и пометку об отсутствии ключа.
- В админке список моделей группируется по поставщику (optgroup), у группы без ключа появляется подсказка с именем недостающей переменной, а сохранение переключения на такую группу отклоняется ошибкой у поля. Текущее значение с исчезнувшим ключом не блокирует сохранение остальных полей вкладки.
- Клиент переименовывается из `DeepSeekClient` в `LlmClient`: он больше не про DeepSeek. `HttpClient` становится подменяемым, чтобы тест мог проверить адрес и ключ для выбранной модели.
- Область не меняется: `aiModel` по-прежнему хранит идентификатор модели без префикса, поэтому миграция базы не нужна.

## Capabilities

### New Capabilities

- `llm-provider`: каталог провайдеров и моделей, источник ключей, выбор активной модели, поведение при отсутствии ключа у выбранной модели, поставщик и наличие ключа в уведомлении о запуске.

### Modified Capabilities

- `admin-console`: требование «Модель выбирается из списка» — группировка по поставщику и подсказка об отсутствии ключа.
- `runtime-configuration`: требование «Запуск с конфигурацией из переменных окружения» — ключи `BOT_AI_KEY_<ID>` вместо `BOT_AI_KEY`, отсутствие ключа ИИ не блокирует запуск.

## Impact

- `src/main/java/org/example/AiChat/DeepSeekClient.java` — переименование и выбор провайдера по модели.
- `src/main/java/org/example/Settings/Settings.java` — плоский список моделей заменяется каталогом.
- `src/main/java/org/example/Config/BotProperties.java` — `bot.ai.key.<id>` вместо обязательного `bot.ai.key`.
- `src/main/java/org/example/Admin/AdminSettingsController.java`, `AdminSettingsValidator.java`, `src/main/resources/templates/admin/settings.html` — группированный список, подсказка, ошибка сохранения.
- `src/main/java/org/example/StartupNotifier.java` — провайдер и пометка об отсутствии ключа в уведомлении.
- `.github/workflows/deploy.yml` — новые строки `BOT_AI_KEY_<ID>` в `bot.env`; новые секреты репозитория.
- `.vscode/launch.json` — `BOT_AI_KEY` → `BOT_AI_KEY_DEEPSEEK` в обеих конфигурациях.
- Тесты: `AiService`, `AnswerPlanner`, `AnswerGenerator`, `AiMemoryExtractor`, `MemoryScheduling`, `StartupNotifier` и десять MockMvc-тестов админки (`bot.ai.key=sk-test` → `bot.ai.key.deepseek=sk-test`).
- База данных и миграции не меняются.
- Открытый риск: если в проде `aiModel` = `deepseek-chat`, а этой модели в документации DeepSeek больше нет, удаление её из каталога сделает бота немым. Значение проверяется до правки каталога.
