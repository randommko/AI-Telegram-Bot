# Spec Delta

## MODIFIED Requirements

### Requirement: Запуск с конфигурацией из переменных окружения

Система SHALL получать конфигурацию запуска (токен бота, URL базы данных, пользователь БД, пароль БД) из переменных окружения `BOT_TOKEN`, `BOT_DB_URL`, `BOT_DB_USER`, `BOT_DB_PASSWORD`, ключи провайдеров ИИ — из отдельных переменных `BOT_AI_KEY_<ID>`, а пароль и адрес веб-админки — из `BOT_ADMIN_PASSWORD`, `BOT_ADMIN_PORT`, `BOT_ADMIN_BIND`, и MUST NOT требовать файл конфигурации или позиционные аргументы командной строки.

#### Scenario: Запуск с полным набором переменных окружения

- **WHEN** приложение запускается, когда заданы `BOT_TOKEN`, `BOT_DB_URL`, `BOT_DB_USER`, `BOT_DB_PASSWORD` и ключ провайдера `BOT_AI_KEY_DEEPSEEK`
- **THEN** приложение использует переданные значения и запускает бота

#### Scenario: Отсутствует обязательная переменная

- **WHEN** приложение запускается, когда одна из переменных `BOT_TOKEN`, `BOT_DB_URL`, `BOT_DB_USER`, `BOT_DB_PASSWORD` не задана или пуста
- **THEN** приложение завершается с ненулевым кодом и сообщением, называющим переменную, не пытаясь подключиться к базе данных или Telegram

#### Scenario: Конфигурация передана аргументами командной строки

- **WHEN** приложение запускается с позиционными аргументами `token dbUrl dbUser dbPassword`
- **THEN** эти аргументы не используются как конфигурация, а запуск завершается с ошибкой обязательных переменных окружения

#### Scenario: Переменные админки не заданы

- **WHEN** приложение запускается без `BOT_ADMIN_PASSWORD`, `BOT_ADMIN_PORT` и `BOT_ADMIN_BIND`
- **THEN** бот запускается и работает как обычно, админка недоступна, а пустые необязательные переменные не считаются ошибкой конфигурации

#### Scenario: Ключа ИИ нет ни у одного провайдера

- **WHEN** приложение запускается без единой переменной `BOT_AI_KEY_<ID>`
- **THEN** приложение запускается, пишет в лог ошибку об отсутствии ключа у выбранной модели и обрабатывает сообщения, не требующие модели
