# Proposal

## Why

Сейчас «персона» — это строка промпта в `bot_settings` (`aiPromtMyChatContext` для «синего» чата, иначе `aiPromtContext`), а память — плоский лог `ai_messages` на 100 последних сообщений, который целиком уходит в модель. Бот не может быть персонажем: у него нет устойчивых фактов о себе и о людях в чате, нет структурированных воспоминаний, а обращение по имени срабатывает только с начала сообщения и только по списку имён, зашитому в код. Пока это не исправлено, админка персон (#57–#62) и характер в ответах (#51) строить не на чем.

## What Changes

- Новая схема в `migrations/004_personas_and_memories.sql`: персона чата, алиасы, словарь категорий, воспоминания с важностью и ядром, связь воспоминаний с людьми, watermark фонового анализа, а также таблицы настроения и обид из #51 (создаются заранее, используются в #51). Сиды: настройки `aiMemoryPromptSize`, `aiMemoryAnalyzeEvery`, `aiMemoryExtractPrompt`, шаблоны входа/выхода и персона «Юра», мигрированная из `aiPromtMyChatContext` запросом `INSERT ... SELECT` — текст промпта в git не попадает.
- Промпт чата берётся из персоны, привязанной к чату; если персоны нет — прежняя цепочка `aiPromtMyChatContext`/`aiPromtContext`, затем дефолт. Читается на каждый запрос, без кеша: правка промпта применяется без рестарта. **BREAKING** для «синего» чата: после появления персоны `bot_settings.aiPromtMyChatContext` на ответы больше не влияет.
- Обращение к персоне распознаётся по алиасам из БД в **любом месте** сообщения и только как целое слово: «юра, как дела?» и «как дела, юра?» вызывают AI, «юрист» и «юрта» — нет. **BREAKING**: раньше имя в середине сообщения намеренно не считалось обращением.
- Текст вопроса — исходное сообщение целиком: разобранное «вопрос без обращения» никогда не уходило в модель, оно лишь решало, вызывать ли AI. Пустой остаток после вычитания имени по-прежнему даёт подсказку без вызова.
- Ответ на реплай сообщению самого бота в выделенном чате — второй триггер, даже без имени в тексте.
- Фоновый анализ переписки отдельным запросом к модели, когда в чате накопилось `aiMemoryAnalyzeEvery` (старт 50) новых сообщений: строгий JSON `add`/`update`/`delete`, валидация категорий, важности, дат и людей, транзакция на прогон, watermark в `memory_analysis_state`.
- Ядровые воспоминания (`is_core`) защищены: анализ может их обновить, но не удалить и не создать; они всегда и целиком попадают в системный промпт, обычные — топ-N по важности и свежести (`aiMemoryPromptSize`, старт 30).
- Ограничение «только `MY_CHAT_ID`» сохраняется для обоих триггеров; персоны в любых чатах — задача #62.

## Capabilities

### New Capabilities

- `persona`: персона, привязанная к чату, — источник промпта и алиасов обращения; поведение чата без персоны.
- `persona-memory`: долговременные воспоминания персоны — извлечение из переписки фоновым анализом, правила ядра и попадание памяти в системный промпт.

### Modified Capabilities

- `ai-invocation`: обращение по имени переезжает с начала сообщения на любое место, список имён заменяется алиасами персоны из БД, добавляется триггер «реплай сообщению бота», снимается требование «вопрос отделяется от обращения».
- `ai-chat-memory`: источник системного промпта — персона чата, затем настройка, затем дефолт, с сохранением актуальности без рестарта.

## Impact

- Код: новый `migrations/004_personas_and_memories.sql`; `AiChat/` — `PersonaRepository`, `PersonaService`, `AiAddressParser` (алиасы из БД, любое место), `AiService` (промпт персоны, блок памяти), `MemoryRepository`, `MemoryPromptBuilder`, `AiMemoryExtractor`, `MemoryWriter`; `CommandDispatcher` (реплай, гейт `MY_CHAT_ID`); `Settings/Settings` и `Settings/TablesDB` (новые ключи и таблицы); `Main` (`@EnableScheduling`).
- Конфигурация: новых переменных окружения нет; новые ключи `bot_settings` создаются миграцией. Модель и её параметры остаются глобальными — настройки персоны их не трогают.
- Данные: миграция аддитивная, существующие таблицы и строки не меняются. В прод накатывается от владельца схемы **до** пуша, иначе `app_user` получит `permission denied`.
- Вне scope: настроение и обиды в ответах (#51), инициатива, админка (#57–#61), персоны в любых чатах (#62), внешние источники (#63). Проанализировать удастся только удержанное окно `ai_messages`, старые сообщения не восстанавливаются.
