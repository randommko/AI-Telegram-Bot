# Design

## Context

Проход чтения шлёт запросы с зашитым потолком 500 токенов; в живом журнале 2026-11-10 модель polza с рассуждениями списала весь лимит на размышления, ответ опустел и пачка была пропущена. Остальные бюджеты (ответ, план, анализ памяти) уже настраиваются через админку или подняты polza-provider — у реакций осталась последняя константа. Мотивация — в proposal.md («Why»); требования — в дельтах `specs/message-reactions/spec.md` и `specs/admin-console/spec.md`.

## Goals / Non-Goals

**Goals:**

- Бюджет запроса прохода становится настройкой `aiReactionMaxTokens` на вкладке «Реакции», читаемой на каждый проход.
- Дефолт 2000 токенов: запас покрывает рассуждения и короткий JSON-ответ у рассуждающих моделей.
- Документация (README, «Вики») обновляется вместе с настройкой.

**Non-Goals:**

- Вне объёма по proposal: отключение рассуждений на уровне модели, смена модели реакций, правка других бюджетов, автоматический накат миграции.

## Decisions

### Д1. Настройка на вкладке «Реакции», диапазон 1..8192, дефолт 2000

Поле стоит рядом с размером пула и паузой — это параметры одного прохода. Диапазон совпадает с общим потолком бюджетов в валидаторе настроек.

- Альтернатива: только поднять зашитую константу до 2000 без настройки — отклонена владельцем: он хочет управлять размером из админки, как остальными бюджетами.
- Альтернатива: переиспользовать `maxTokensQuestion` — отклонена: у реакций своя модель, отдельный бюджет позволяет дешёвой модели реакций не зависеть от щедрости основной.
- Альтернатива: отдельная страница настроек прохода — отклонена: поле относится к уже существующей вкладке, новых страниц не нужно.

### Д2. Чтение на каждый проход, константа остаётся запасной

Значение читается из настроек при каждом запуске прохода, как и остальные параметры функции. Прежняя константа становится запасным значением по умолчанию (2000) на случай пустой или некорректной настройки — так же устроены остальные целочисленные настройки.

- Альтернатива: читать значение при старте процесса — отклонена: нарушает общее правило «настройки применяются без перезапуска».

### Д3. Миграция добавляет строку настроек, seed — для чистой базы

Для живой базы — идемпотентный файл с `INSERT ... ON CONFLICT DO NOTHING` по образцу существующих миграций настроек; для чистой базы та же строка добавляется в seed. Значения у существующей базы не перезаписываются: строка новая, конфликта с ручными правками нет.

- Альтернатива: UPDATE-подход как в polza-provider — не нужен: настройка новая, старого значения не существует.

## Risks / Trade-offs

- [Большой лимит повышает расход токенов] → расход растёт по фактическим токенам, а не по лимиту; реакции редкие и дешёвые (на `z-ai/glm-5.3-flash` 2000 токенов ≈ 0,02 ₽ за проход).
- [Документация отстанет от настройки] → обновление README и раздела «Вики» включено в задачи, вики — документация механик, отстаёт молча.
- [Валидатор без диапазона пропустит мусор] → общий диапазон бюджетов 1..8192 в валидаторе настроек.

## Migration Plan

1. Миграция настроек — новый идемпотентный файл в `migrations/config/`, накат вручную на сервере. Порядок с выкаткой не важен: до наката проход работает на запасном дефолте.
2. Выкатка: слияние в `main` запускает Deploy bot и Deploy admin.
3. Откат: значение правится в админке; сама настройка откату не мешает — при её отсутствии проход использует запасное значение.

## Open Questions

Нет: имя настройки, место, диапазон и дефолт зафиксированы решениями выше.
