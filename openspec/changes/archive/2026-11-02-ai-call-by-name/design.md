# Design

## Context

- `CommandDispatcher.dispatch` (`CommandDispatcher.java:84-118`) при `!text.startsWith("/")` вызывает `saveMessageText` и выходит, поэтому текст без слэша никогда не доходит до `AiService`.
- Ветка команды уже умеет сохранять аргумент: при `parts.length > 1` в историю пишется `parts[1]`, а сама команда отбрасывается (`CommandDispatcher.java:100-105`).
- `AiService.askAi(Message)` (`AiService.java:43-58`) сам разбирает текст команды: `split(" ", 2)`, вопрос — вторая часть; при пустом вопросе отправляет «Напиши свой вопрос после команды /ai».
- Слэш-алиасы AI уже включают `/юра`, `/юрий`, `/юрец` (`CommandDispatcher.java:30`), поэтому «переименование» из #44 в этой части уже сделано; новая работа — только распознавание обращения без слэша.
- `Settings.MY_CHAT_ID = -1001347887839L` — существующая константа «синего» чата; она же выбирает специальный системный промпт в `AiService.getSystemPrompt`.
- Тестового покрытия у `CommandDispatcher` нет; `AiServiceTest` работает на моках `SettingsService`, `DeepSeekClient`, `AiChatRepository`, `MessageSender`.

## Goals / Non-Goals

**Goals:**

- Обращение по имени в выделенном чате превращается в вопрос к AI без слэша.
- Обращение распознаётся как отдельное слово и не срабатывает на «юрист», «юрта», «юркий».
- Разбор текста вопроса покрыт unit-тестами без Spring-контекста и без сети.

**Non-Goals:**

- Пункты тела #44 вне комментария владельца: переименование викторины, аватар бота, «починить бота».
- Настройка списка обращений и чата через `bot_settings` — до появления такого запроса список остаётся константой в коде.
- Подключение `/summary` и любые изменения лимита истории.

## Decisions

### D1. Отдельный парсер, а не ветка в диспетчере

Новый `org.example.AiChat.AiAddressParser` — обычный бин без зависимостей с одним методом:

```java
Optional<String> question(String text)
```

- `Optional.empty()` — сообщение не начинается с обращения;
- `Optional.of("")` — обращение есть, вопроса нет;
- `Optional.of("как дела?")` — вопрос.

`CommandDispatcher` только решает, кому это разрешено (`MY_CHAT_ID`) и что делать с пустым вопросом.

*Альтернатива:* regex прямо в `dispatch` — отвергнута: диспетчер уже отвечает за маршрутизацию всех команд, а разбор текста в нём нечем проверить тестом, кроме моков Telegram-объектов. Парсер проверяется строками.

### D2. Обращение — отдельное слово в начале

Одно регулярное выражение, регистронезависимое, по исходному тексту (регистр вопроса сохраняется):

```
^\s*(?iu:юра|юрец|юрчик|юрий|юр)(?:\s|[,.;:!?…—–-]|$)
```

Хвостовая группа `(?:\s|…|$)` и есть граница слова: «юридический» и «юрта» не совпадают, потому что после «юр» идёт буква, а не разделитель. Список в альтернативе упорядочен от длинных к коротким для читаемости, хотя граница делает порядок несущественным.

*Альтернатива:* `text.toLowerCase().startsWith("юр")` — ровно то поведение, которого спека избегает: «юрист» в выделенном чате уходил бы в AI.

### D3. Вопрос — остаток после обращения и разделителей

Из совпадения берётся конец, затем строка обрезается слева по `[\s,.;:!?…—–-]+` и по пробелам справа. «Юра, как дела?» → «как дела?», «Юрий!» → «», «юр» → «».

### D4. Точка вызова — после сохранения в историю

В `dispatch` порядок такой: сохранить сообщение (существующий `saveMessageText` с полным текстом), затем проверить `MY_CHAT_ID` и `AiAddressParser.question(text)`. Так формат истории `Сообщение от: @nick: <text>` не меняется, а сообщение с обращением участвует в следующих запросах.

Косвенное следствие: обращение сохраняется в историю вместе с текстом — AI видит, что к нему обратились по имени, и это же поведение уже есть для слэш-команд.

### D5. `AiService` получает вопрос, а не `Message`

Добавляется `askAi(Long chatId, String question)`; существующий `askAi(Message)` разбирает команду и делегирует. Логика запроса (история, температура, отправка, сохранение ответа) остаётся в одном месте, дублирования нет.

Пустой вопрос по обращению обрабатывает диспетчер — отправляет короткую подсказку в чат, потому что текст «после команды /ai» для обращения по имени звучит неверно.

*Альтернатива:* передавать в `AiService` флаг «это обращение» — отвергнута: сервису не нужно знать, откуда пришёл вопрос.

### D6. Список обращений — константа в парсере

`MY_CHAT_ID` берётся из существующего `Settings`, чтобы чат задавался в одном месте. Список слов живёт в `AiAddressParser`. Ключа в `bot_settings` нет: настройка появится, только если понадобится менять слова без деплоя.

### D7. Тесты

`AiAddressParserTest` — чистые строки: каждое из пяти обращений, верхний регистр, знаки после обращения, обращение без вопроса, «юридический вопрос», обращение не в начале, обычный текст.

`AiServiceTest` — новый тест, что `askAi(chatId, question)` уходит в `DeepSeekClient` с вопросом без разбора команды.

Привязку к чату проверяет `AiAddressParser`-тест на уровне диспетчера не покрыть без моков Telegram; вместо этого условие `MY_CHAT_ID.equals(chatId)` остаётся однострочным и проверяется вручную в чате после деплоя.

## Risks / Trade-offs

- **Ложное срабатывание в выделенном чате** на редком слове из трёх букв («юр» отдельным словом) → ответ AI вместо тишины; цена — один лишний запрос к DeepSeek, лечится расширением списка слов.
- **«Юра» в начале сообщения в выделенном чате теперь всегда стоит ответа AI**, даже если это цитата или обращение к человеку по имени → принято владельцем задачи: чат сам просил такое поведение.
- **Обращение в начале чужого чата ничего не делает** → ожидаемо по спеке; если позже понадобится, гейт по чату снимается одной строкой.
- **`/юр` без слэша-команды** не заведён как алиас команды: `/юр` остаётся неизвестной командой. В спеке такого требования нет, поведение не меняется.
- **Порядок обработки сохранения и запроса**: если DeepSeek недоступен, сообщение уже в истории, как и для `/ai`; отдельной обработки ошибок не требуется.

## Migration Plan

1. Изменения только в коде: миграций, новых переменных окружения и ключей `bot_settings` нет.
2. `mvn test` — новые тесты парсера и `AiService`.
3. `mvn package` и разовый запуск собранного jar на заглушках (`BOT_TOKEN=1:dummy`, недоступный прокси): бин парсера и `CommandDispatcher` должны подняться. Пуш в `main` сразу выкатывается на живой бот.
4. Проверка в «синем» чате: «Юра, как дела?» → ответ AI; «юридический вопрос» → тишина; `/юра как дела` → ответ как раньше.
5. Откат: revert коммита и повторный пуш; состояние БД не затрагивается.
