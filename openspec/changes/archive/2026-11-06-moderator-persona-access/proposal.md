# Proposal

## Why

Права модератора на персону сейчас выводятся только из чатов: он видит персону, если у него есть хотя бы один её чат, а правит — только когда ему выданы **все** её чаты (`AdminAccess.canEditPersona` через `PersonaRepository.permission`). Из-за этого:

- персону своего чата нельзя вести, если её же привязали к чужому чату;
- создатель персоны теряет её, как только персону привязали к чужому чату;
- выдать модератору доступ к отдельной персоне нельзя вовсе, хотя в #83 это второй, независимый тип прав.

## What Changes

- **BREAKING** — право на чат даёт модератору только просмотр карточки персоны, но не правку.
- **Править персону** может владелец, создатель этой персоны и модератор, которому владелец выдал доступ именно к персоне.
- **Авторство персоны запоминается**: `config.personas.created_by` хранит Telegram id создателя, поэтому персона, созданная модератором, остаётся его и после привязки к чужим чатам.
- **Выдача доступа к персонам** — новая таблица `configurator.moderator_personas` (модератор, персона, кто и когда выдал).
- **Раздел «Модераторы»** у каждой учётки показывает персон, к которым есть доступ, с источником (чат, создал сам, выдан владельцем), и даёт форму выдать и отозвать доступ к персоне.
- **Списки подстраиваются**: «Персоны» показывает только доступное модератору; карточка персоны, доступной лишь через чат, открывается на чтение с пояснением, что правку выдаёт владелец.
- Владелец по-прежнему видит и правит всех персон.

## Capabilities

### New Capabilities

Нет: правила модератора уже описаны возможностью `moderator-access`, туда же попадает и новый раздел выдачи.

### Modified Capabilities

- `moderator-access`: требование «Модератор правит персону, только пока все её чаты его» заменяется правилами «чат — просмотр, персону правят создатель и выданный доступ»; добавляются требования про авторство персоны и выдачу доступа к персонам из раздела «Модераторы»; уточняется, что видит модератор в списке персон.

## Impact

- `migrations/config/001_schema.sql` — колонка `created_by` у `config.personas` (идемпотентно: `ADD COLUMN IF NOT EXISTS`).
- `migrations/configurator/001_schema.sql` — таблица `configurator.moderator_personas`.
- `core/src/main/java/org/example/core/settings/TablesDB.java` — константа новой таблицы.
- `core/.../aichat/PersonaRepository.java` — видимость и правка по персоне вместо «все чаты», запись `created_by` при создании в чате, выборка списка с учётом грантов.
- `admin/.../AdminAccess.java` — правила «чат = просмотр», «создатель/грант = правка».
- `admin/.../ChatModeratorRepository.java` — выдача и отзыв доступа к персонам рядом с выдачей чатов.
- `admin/.../AdminAccountsController.java`, `templates/admin/moderators.html` — список доступных персон и формы выдачи/отзыва.
- `admin/.../AdminPersonaController.java`, `templates/admin/persona-form.html` — текст режима «только чтение».
- `admin/src/test/.../AdminAccessTest.java`, `AdminPersonaTest.java`, новые тесты выдачи доступа.
- База: на прод миграция накатывается вручную — нужны новая таблица и колонка, без них админка не сохранит персону.
