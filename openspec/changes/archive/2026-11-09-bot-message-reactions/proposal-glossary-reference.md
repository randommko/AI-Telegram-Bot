# Glossary Reference

| Term | Source Glossary | Context |
| --- | --- | --- |
| Реакция | `glossary/business.md` | Новое поведение ставит эмодзи под сообщением участника как молчаливое отношение. |
| Каталог эмодзи | `glossary/business.md` | Задаёт набор допустимых реакций и инструкцию модели, правится в админке. |
| Метка памяти | `glossary/business.md` | ✍ присутствует в каталоге, но ставится отдельным шагом позже и в объём не входит. |
| Проход чтения | `glossary/technical.md` | Фоновый разбор пачки сообщений, из которого берутся реакции. |
| Персона | `glossary/business.md` | Отношение к сообщению определяется характером и состоянием персоны. |
| Чат | `glossary/business.md` | Проход работает по чату с назначенной персоной. |
| Участник | `glossary/business.md` | Реакция ставится на сообщение участника, а не на сообщение бота. |
| Эмоция | `glossary/business.md` | Текущее состояние персоны передаётся в контекст прохода, но шкалы не меняются. |
| Обида | `glossary/business.md` | Неприязнь к участнику влияет на выбор реакции. |
| Настройка | `glossary/business.md` | Выключатель, промпт, пул и пауза читаются из настроек на каждый проход. |
| Провайдер | `glossary/business.md` | Своя модель для реакций может быть у другого провайдера, чем модель ответов. |
| Миграция | `glossary/technical.md` | Добавляются Telegram-идентификатор, журнал реакций, отметка и каталог. |
| Возможность | `glossary/technical.md` | Вводится `message-reactions`, правятся `admin-console` и `llm-provider`. |
| Деплой | `glossary/technical.md` | Правки затрагивают оба приложения, поэтому запускаются оба workflow. |
