# Design

## Context

`AdminPersonaValidator.checkAliases` (`admin/src/main/java/org/example/admin/AdminPersonaValidator.java`) отклоняет алиас, если `PersonaRepository.aliasOwner` нашёл его у другой персоны. Схема базы такого ограничения не содержит: `config.persona_aliases` имеет уникальный индекс только по паре `(persona_id, lower(alias))` — это проверено и в файле миграции, и в прод-базе.

Мотивация — `proposal.md`; поведение — дельта `specs/persona/spec.md`.

## Goals / Non-Goals

**Goals:**

- Разрешить одинаковые алиасы у разных персон.
- Сохранить запреты, которые действительно защищают: одно слово без знаков и не команда бота.
- Убрать из кода и интерфейса обещание глобальной уникальности.

**Non-Goals:**

- Не менять схему и миграции: индекс уже нужный.
- Не менять разбор обращения в чате: `PersonaService.aliasesForChat` берёт алиасы персоны этого чата.
- Не менять подсказки, которые касаются формата и команд.

## Decisions

**Проверка снимается в валидаторе, а не «ослабляется» в SQL.** Уникального индекса по одному `alias` в базе нет, поэтому достаточно убрать вызов `aliasOwner`; никаких `DROP INDEX` и миграций не требуется. Альтернатива — оставлять глобальный индекс и ловить нарушение по ошибке вставки — дала бы невнятное сообщение вместо работы.

**`PersonaRepository.aliasOwner` удаляется.** После снятия проверки метод не используется нигде: форма опирается на валидатор. Оставлять мёртвый метод с глобальным запросом — приглашение вернуть ограничение случайно.

**Внутри одной персоны уникальность остаётся двойной.** `parseAliases` уже отбрасывает повторы без учёта регистра, а индекс `(persona_id, lower(alias))` не даст записать дубль даже в обход формы.

**Подсказка и README объясняют, почему совпадение безопасно.** В карточке: «Может совпадать с алиасом другой персоны: в чате всегда одна персона». Это снимает вопрос «почему у двух персон одно имя» у владельца и модератора.

## Risks / Trade-offs

- **Две персоны с одним именем в списке админки** → список и так показывает привязанные чаты и число алиасов; различать их можно по чатам. Приемлемо: имена персон и раньше не были уникальными.
- **Пользователь может завести «Юру» в двух чатах и ждать разных ответов по одному имени** → в каждом чате отвечает своя персона, потому что обращение разрешается по чату; это ровно то поведение, которое просит #82.
- **Модератор видит чужую персону с тем же алиасом в списке доступных** → список ограничен его правами (чат/создал/выдан), лишнего он не увидит.

## Migration Plan

Миграций нет. Деплой обычный: правка `admin/` и `core/` перезапускает админку и бота. Откат — revert коммита.
