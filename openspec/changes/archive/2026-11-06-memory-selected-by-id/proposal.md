# Proposal

## Why

План ответа выбирает воспоминания по id, но при сборке промпта генерации выбранное ищется только среди топ-N по важности. Запись за пределами топ-N молча теряется, а если не совпал ни один id — подставляются все топ-N. Модель получает не то, что выбрала, и в логе об этом нет ни строки (задача #85).

## What Changes

- Новый метод `MemoryRepository.findByIds(personaId, ids)`: выборка по идентификаторам с условиями «эта персона» и «не удалено».
- `PromptComposer.memories()` тянет выбранные воспоминания этим методом вместо фильтрации среза топ-N; ядро по-прежнему прикладывается целиком.
- Неизвестные и чужие идентификаторы отбрасываются с предупреждением в лог.
- Пустой или полностью невалидный выбор сохраняет прежний фолбэк: все обычные воспоминания из топ-N.
- Тесты: выбор вне топ-N попадает в промпт, невалидный id не ломает запрос.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `prompt-composition`: требование «Память генерации ограничивается выбором плана» — выбор больше не ограничен топ-N, а фолбэк остаётся прежним.

## Impact

- `core/src/main/java/org/example/core/aichat/MemoryRepository.java` — выборка по id.
- `core/src/main/java/org/example/core/aichat/PromptComposer.java` — сборка раздела памяти.
- Тесты `PromptComposerTest`.
- Поведение бота меняется только там, где план выбирал воспоминание за пределами топ-N; остальные ответы не затрагиваются.
