# Design

## Context

Раздел «Люди» собирался из `findLastMessages(chatId, 50)` и обрезался до 10 авторов в Java. Сила обиды считается в `PersonaGrudgeService` модуля бота, а `PromptComposer` живёт в core и не может зависеть от бота.

## Approach

1. `AiChatRepository.findAuthorStats(chatId, limit)` — группировка по автору по всей истории с числом сообщений и максимальным id для порядка «самые свежие первыми».
2. `PromptComposer.people()` строит строки `@ник (Имя) — N сообщений[, обида M][ — сейчас пишет]`; первый в списке считается пишущим сейчас.
3. `GrudgeStrength` в core — общая формула действующей силы обиды; `PersonaGrudgeService.effective` делегирует в неё, поведение не меняется.
4. `PromptSection.PEOPLE` — бюджет 1200 символов; `add()` пишет WARN при превышении.

## Decisions

- **Окно — вся история, лимит — на уровне SQL.** Считать авторов в Java по всем сообщениям дороже и требует тянуть историю в память; группировка в базе отдаёт сразу десять строк.
- **Число сообщений и обида, без дат и цитат.** Бюджет раздела ограничен; дата последнего сообщения модели не нужна, а «сколько пишет» и «обижен ли» меняют тон ответа.
- **Формула обиды вынесена в core.** Дублировать расчёт в двух модулях хуже, чем один общий класс: расхождение дало бы разные силы в промпте и в плане.
- **Бюджет 1200, а не безлимит.** Десять строк с фактами — примерно 900–1100 символов; 1200 оставляет запас и ловит разрастание.

## Risks

- `max(author_nick)` берёт лексикографически максимальный ник, а не последний. Ник меняется редко; при смене возможна строка со старым ником до следующего сообщения.
- Участник без ника подписывается только именем — так же, как раньше.
