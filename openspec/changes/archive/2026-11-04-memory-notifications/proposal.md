# Proposal

## Why

Обновления памяти сейчас видны только числами в журнале: `Анализ памяти в чате …: добавлено 2, обновлено 1, удалено 0`. Что именно персона запомнила, изменила или забыла, владелец узнаёт лишь открыв админку, а с несколькими персонами следить за этим вручную нереально. Задача #65 просит присылать эти обновления в личку разработчику.

## What Changes

- **После прогона анализа памяти с изменениями владельцу приходит одно сообщение** в Telegram: имя персоны, чат (название и id), сколько сообщений разобрано, затем списки — добавлено (категория, важность, текст), изменено (было → стало, если текст менялся), удалено (категория, важность, текст), отброшено попыток удалить защищённую запись.
- **Уведомляет любой прогон анализа**: фоновый по порогу `aiMemoryAnalyzeEvery` и кнопка «Проанализировать» в админке — оба идут через один и тот же метод. Ручные правки, удаления и возвраты в форме админки не уведомляют: их делает человек, и они уже пишутся в журнал `admin_changes`.
- **Нет изменений — сообщения нет.** Пустой прогон (0 добавлено, 0 обновлено, 0 удалено) молчит, иначе при пороге в 50 сообщений личка превращается в шум.
- **Уведомление можно выключить в админке.** На вкладке «Уведомления» рядом с получателем появляется флажок «Присылать обновления памяти» — новая настройка `aiMemoryNotifyOwner`, по умолчанию включена. Снятый флажок или пустой получатель выключают отправку, анализ памяти при этом продолжается.
- **Отправка идёт после записи памяти.** Её сбой пишется в лог и не откатывает уже сохранённые воспоминания; длинный текст режется на части по лимиту Telegram.
- В настройках админки появляется вид поля «флажок» — сейчас его там нет, хотя в карточке персоны такие поля уже есть.

## Capabilities

### New Capabilities

Нет: поведение относится к уже описанным возможностям памяти и админки.

### Modified Capabilities

- `persona-memory`: новое требование — обновления памяти сообщаются владельцу в Telegram; состав сообщения, молчание без изменений, выключение и независимость записи памяти от отправки.
- `admin-console`: требование «Настройки разделены на вкладки» — на вкладке «Уведомления» теперь два поля: получатель и флажок уведомлений о памяти.

## Impact

- `src/main/java/org/example/AiChat/AiMemoryExtractor.java` — после успешного `apply` собирает и отправляет отчёт; при отключённых уведомлениях и без изменений не отправляет.
- Новый класс-отправитель (условно `MemoryUpdateNotifier`) — форматирование сообщения и отправка через `MessageSender.sendLongMessage`; сбой отправки только логируется.
- `src/main/java/org/example/AiChat/PersonaRepository.java` — имя персоны для заголовка (`findForChat` уже умеет), безопасное чтение названия чата через `ChatsService`.
- `src/main/java/org/example/Admin/AdminSettingsController.java`, `src/main/resources/templates/admin/settings.html` — вид поля `checkbox`, флажок `aiMemoryNotifyOwner` на вкладке «Уведомления», сохранение снятого флажка как `false`.
- `src/main/java/org/example/Settings/Settings.java` — ключ `aiMemoryNotifyOwner`.
- `migrations/` — INSERT-миграция настройки с описанием для подсказки (i).
- Тесты: новый тест форматтера/отправителя; `AiMemoryExtractorTest` (есть изменения → отправка, нет изменений → тишина, уведомления выключены → тишина, сбой отправки не ломает анализ); `AdminSettingsTest` (флажок на вкладке и сохранение `false`).
- Схема БД не меняется; миграция только вставляет строку `bot_settings`. Конфиг, деплой и переменные окружения не затрагиваются.
- Риск: частые сообщения в активном чате. Смягчение — порог анализа, молчание при нулевых изменениях и флажок в админке.
