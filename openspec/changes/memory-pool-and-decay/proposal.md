# Proposal

## Why

План ответа получает каталог «ядро + топ-30 по важности». Топ-30 не учитывает, о ком идёт речь: события самого активного участника вытесняются событиями других людей, а старое событие с высокой базовой важностью стоит выше свежего. Из-за этого модель выбирает воспоминания, не связанные с текущим разговором (задача #86).

## What Changes

- Пул кандидатов для плана: топ-15 событий, связанных с автором сообщения-триггера, плюс по топ-10 каждого другого типа воспоминаний.
- Если у автора нет событий, пул берёт общие события, чтобы не остаться без них.
- Важность события со временем убывает — как у эмоций: линейно, при чтении, от даты события (или даты создания записи), не ниже 1. Друзья, семья, хобби и работа не стареют.
- Скорость задаётся настройкой «Дней на балл затухания событий» (по умолчанию 3; 0 — выключено).
- В промпте печатается действующая важность, а не исходная.
- Пул ограничен бюджетом символов: лишние записи отбрасываются с предупреждением в лог.
- В контексте плана убирается отдельный блок памяти — его заменяет каталог с идентификаторами, чтобы модель не видела воспоминания, которые нельзя выбрать.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `prompt-composition`: добавляются требования о правиле пула и о затухании важности событий; существующая сборка промпта не меняется.

## Impact

- `core/src/main/java/org/example/core/aichat/`: `MemoryDecay`, `MemoryRecord`, `MemoryRepository`, `PromptComposer`, `MemoryPromptBuilder`.
- `bot/src/main/java/org/example/bot/aichat/`: `AnswerPlanner` (автор триггера и каталог пула), `AiService` (передача автора).
- `admin/src/main/java/org/example/admin/AdminSettingsController.java` — настройка затухания на вкладке «Память».
- `migrations/config/003_memory_decay.sql` — строка настройки с описанием (накатывается владельцем).
