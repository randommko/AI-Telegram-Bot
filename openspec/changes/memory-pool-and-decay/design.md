# Design

## Context

`AnswerPlanner` собирает каталог из `memoryPool(chatId)` — ядро плюс топ-N по базовой важности. `MemoryRecord` не знает даты создания, а формула затухания должна считаться при чтении, без планировщика.

## Approach

1. `MemoryDecay` — компонент с формулой: `max(1, база − дни / дней_на_балл)`. Читает настройку, часы получает из `Clock`. Статическая часть покрыта тестами без базы.
2. `MemoryRecord` получает `createdAt` (десятый компонент), старые конструкторы сохранены — дата создания нужна как точка отсчёта, когда у события нет `event_date`.
3. `MemoryRepository`: выборка событий автора (`findEvents(personaId, userId)`), общих событий и обычных записей вне событий. Сортировка и лимиты — в Java: объёмы небольшие, а формула живёт в одном месте.
4. `PromptComposer.memoryPool(chatId, authorUserId)`: события автора → топ-15; обычные → группировка по типу → топ-10; общий бюджет 30 000 символов.
5. `MemoryPromptBuilder` печатает действующую важность через `MemoryDecay`.
6. Контекст плана больше не содержит отдельного блока памяти: каталог с идентификаторами и важностью его заменяет.

## Decisions

- **Считать в Java, а не SQL.** Формула одна и та же для ранжирования и для печати, её можно протестировать без базы. При росте памяти выражение переедет в SQL с индексом.
- **Категория «события» — константа `MemoryRepository.EVENT_CATEGORY`.** Код справочника редактируемый, поэтому имя собрано в одном месте и используется в запросах параметром.
- **Записи без `event_date` стареют от `created_at`, не от `updated_at`.** Правка текста не делает старое событие свежим.
- **Стареют только события.** Друзья, семья, хобби, работа и ядро сохраняют важность: это факты, а не происшествия.
- **Бюджет пула в символах — константа, а не настройка.** Это предохранитель от роста, а не ручка управления поведением.

## Risks

- Пул может стать заметно больше прежних 33 записей: 15 событий плюс по 10 на каждый тип. На проде это ≈13k символов против 14,5k — не рост, но при добавлении типов пул расширяется.
- Без наката `migrations/config/003_memory_decay.sql` настройка работает на значении по умолчанию, но без описания в админке.
- В списке воспоминаний админки по-прежнему показывается базовая важность; действующая видна в предпросмотре промпта.
