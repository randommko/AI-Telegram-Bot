# Spec Delta

## ADDED Requirements

### Requirement: Прямое подключение к Telegram Bot API

Система SHALL подключаться к Telegram Bot API напрямую, без прокси, и MUST NOT читать переменные `BOT_PROXY_*`. Доступность API обеспечивает сетевая конфигурация хоста: на сервере — маршруты VPN, при локальном запуске — режим TUN.

#### Scenario: Запуск с прямым подключением

- **WHEN** AI-бот запускается, а переменные `BOT_PROXY_*` не заданы
- **THEN** бот регистрируется в Telegram и получает обновления без прокси

#### Scenario: Переменные прокси остались в окружении

- **WHEN** в окружении остались `BOT_PROXY_HOST` и `BOT_PROXY_PORT` от прежней версии
- **THEN** бот их игнорирует и подключается к Telegram напрямую

### Requirement: Проверка конфигурации запуска до подключения к внешним сервисам

Система SHALL проверять значения конфигурации запуска до подключения к PostgreSQL и Telegram Bot API и MUST NOT начинать обработку сообщений при невалидных значениях.

#### Scenario: Некорректный порт админки

- **WHEN** задан `BOT_ADMIN_PORT` вне диапазона 1..65535
- **THEN** запуск прерывается ошибкой, называющей переменную, и приложение не подключается к PostgreSQL

## MODIFIED Requirements

### Requirement: Запуск с конфигурацией из переменных окружения

Система SHALL получать конфигурацию каждого приложения из его собственных переменных окружения. AI-бот MUST получать `BOT_TOKEN`, `BOT_DB_*` и ключи `BOT_AI_KEY_<ID>`; MAY получать `BOT_ADMIN_PASSWORD`, `BOT_ADMIN_PORT`, `BOT_ADMIN_BIND`, `BOT_SSH_USER` и `BOT_SSH_HOST` для уведомления о запуске. Админка MUST получать `BOT_DB_*`, `BOT_ADMIN_PASSWORD`, `BOT_ADMIN_PORT` и `BOT_ADMIN_BIND` и MUST NOT получать ни ключи провайдеров, ни `BOT_TOKEN`. Оба приложения MUST NOT требовать файл конфигурации или позиционные аргументы командной строки.

#### Scenario: Запуск с полным набором переменных окружения

- **WHEN** AI-бот запускается с `BOT_TOKEN`, `BOT_DB_*` и ключом `BOT_AI_KEY_DEEPSEEK`
- **THEN** приложение использует переданные значения и запускает бота

#### Scenario: Запуск админки с полным набором переменных

- **WHEN** админка запускается с `BOT_DB_*` и `BOT_ADMIN_PASSWORD`
- **THEN** приложение поднимает админку, не обращаясь ни к ключам провайдеров, ни к Telegram

#### Scenario: Отсутствует обязательная переменная

- **WHEN** у приложения не задана одна из его обязательных переменных: `BOT_TOKEN` у бота или любая из `BOT_DB_URL`, `BOT_DB_USER`, `BOT_DB_PASSWORD`
- **THEN** это приложение завершается с ненулевым кодом и сообщением с именем переменной, не подключаясь к базе и Telegram

#### Scenario: Переменные админки не заданы

- **WHEN** AI-бот запускается без `BOT_ADMIN_PASSWORD`, `BOT_ADMIN_PORT` и `BOT_ADMIN_BIND`
- **THEN** бот запускается и работает как обычно, а в уведомлении о запуске нет ссылки на админку и строки туннеля

#### Scenario: Ключа ИИ нет ни у одного провайдера

- **WHEN** AI-бот запускается без единой переменной `BOT_AI_KEY_<ID>`
- **THEN** он запускается, публикует статус «ключа нет» и обрабатывает сообщения, не требующие модели

#### Scenario: Конфигурация передана аргументами командной строки

- **WHEN** приложение запускается с позиционными аргументами вместо переменных окружения
- **THEN** аргументы не используются как конфигурация, а запуск завершается с ошибкой обязательных переменных

## REMOVED Requirements

### Requirement: Подключение к Telegram Bot API через конфигурируемый прокси

**Reason**: Поддержка прокси в приложении не использовалась: в проде `BOT_PROXY_*` пусты, а Telegram доступен через маршруты OpenVPN-клиента `tg-relay` на сервере. В библиотеке 10.x прокси настраивается через OkHttp, и сохранять отдельную ветку конфигурации ради неиспользуемой возможности не нужно.

**Migration**: Убрать `BOT_PROXY_*` из окружения и GitHub Secrets. На сервере доступ к Telegram обеспечивают маршруты VPN; при локальном запуске нужен VPN в режиме TUN. Код настройки прокси удаляется вместе с переменными.

### Requirement: Проверка конфигурации до подключения к внешним сервисам

**Reason**: Оба сценария этого требования проверяли только параметры прокси, которых больше нет. Общая гарантия «невалидный обязательный параметр останавливает запуск» сохраняется в требовании «Запуск с конфигурацией из переменных окружения».

**Migration**: Проверка перенесена в требование «Проверка конфигурации запуска до подключения к внешним сервисам»; сценарии прокси удалены вместе с переменными.
