# Design

## Context

Сейчас `AiService.getHistoryInChat` добавляет три системных сообщения (промпт, блок настроения, блок памяти) и счётчик сбросов, а затем последние N сообщений. Автор сообщения — префикс `"Сообщение от: @ник (Имя): "` внутри `content`; `ai_messages` обрезается до `aiHistorySize` (100) при каждой записи, а `created_at` в таблице есть, но `findLastMessages` его не читает. Читателей два: `AiChatRepository.findLastMessages` (role, content) и `MemoryRepository.findNewMessages` (id, content, created_at).

Настройки — плоские ключи `bot_settings` с описанием; админка строит поля из списка `TabView`/`FieldView`. `EmotionService.blockFor` отдаёт готовый блок с заголовком, фразы фраз берутся из `emotion_phrases`. `PersonaService` отдаёт `id, name, prompt`, а числовые параметры персоны читает только админка. `MessageSender.sendMessage` отправляет текст как есть.

Ограничение по персональным данным: значения промптов в `bot_settings` содержат реальные имена и ники, поэтому в репозиторий и миграцию попадают только нейтральные заготовки, а настоящие значения выставляются вручную на сервере.

## Goals / Non-Goals

**Goals:**

- Один системный промпт, собранный из разделов, с порядком и бюджетами из спеки `prompt-composition`.
- Автор сообщения как данные: ID, ник, имя в колонках, единый вид подписи на входе модели.
- Разделы «люди» и «время» с настройками часового пояса и шаблонов.
- Правка шаблонов и справочника эмоций из админки без перезапуска, предпросмотр собранного промпта.
- Доставка ответа длиннее лимита Telegram.

**Non-Goals:**

- Обиды, два запроса план/генерация, мультиреплики и инициатива — это #51; раздел «обиды» заводится без данных.
- Поиск по истории и её архивация сверх лимита 100 сообщений.
- Внешние источники и инструменты (#63).
- Перенос технической части из `personas.prompt` — ручная правка данных после выката.

## Decisions

### 1. Автор — колонки, `content` — чистый текст

`ai_messages` получает `author_user_id bigint NULL`, `author_nick varchar(64) NULL`, `author_name varchar(128) NULL`. Ник хранится в том же виде, что в `tg_users` (с ведущим `@`); форматтер нормализует его, снимая и добавляя `@`, поэтому двойного `@@` не будет.

Подпись на входе модели остаётся прежней: `@ник (Имя): текст`. Её формирует один форматтер, общий для истории и для анализа памяти, поэтому вид запроса к модели не меняется.

Внешнего ключа на `tg_users` нет: лог переписки не должен зависеть от справочника пользователей. `author_user_id` при выводе раздела «люди» соединяется с `tg_users` через `LEFT JOIN`, а если строки нет — используется сохранённый ник.

Альтернативы: оставить префикс и добавить колонки параллельно (данные дублируются и расходятся, `user_id` всё равно нет); разбирать префикс при чтении (ломается на тексте, содержащем ту же строку). Обе отклонены.

### 2. Текущий автор не передаётся параметром

Вопрос сохраняется в историю до вызова AI (`CommandDispatcher.dispatch` → `saveMessageText`, затем `askAi`), поэтому «сейчас пишет» — это автор последнего сообщения с ролью `user` в собранной истории. `PromptComposer` получает только `chatId`, а `saveMessage` расширяется параметрами автора. Это снимает протаскивание `User` через `AnswerNameAddress` и `askAi(chatId, question)`.

### 3. Реестр разделов — в коде, тексты — в `bot_settings`

Порядок, ключи, заголовки и бюджеты разделов задаёт код (спека запрещает менять порядок настройкой), а редактируемый текст лежит в `bot_settings` с заготовкой в коде для «вернуть по умолчанию». Так порядок нельзя сломать из админки, а текст правится без деплоя.

Новые ключи: `aiPromptTechnical`, `aiPromptEmotionsHeader`, `aiPromptGrudgesHeader`, `aiPromptMemoryCoreHeader`, `aiPromptMemoryRegularHeader`, `aiPromptPeopleHeader`, `aiPromptTimeTemplate`, `aiPromptTimeZone`, `aiPromptAnswerFormat`, `aiPromptServiceTemplate`.

Раздел памяти и список людей сохраняют форматирование строк в коде: дата, важность и люди — часть контракта данных, а не вкус. Редактируется заголовок и общий текст раздела. Шаблон времени содержит `{date}`, `{time}`, `{weekday}`, `{zone}`; шаблон служебного — `{resets}`; техника — `{maxLength}`. Неизвестный плейсхолдер остаётся как есть и виден в предпросмотре.

`BotSettings`-значения читаются на каждый запрос, как остальные настройки.

### 4. Композер — чистый текст, сборка сообщений отдельно

`PromptComposer.compose(chatId)` возвращает `List<Section>` и итоговый текст, не трогая `ArrayNode`. `AiService` добавляет системное сообщение и историю, отрендеренную общим форматтером. Предпросмотр печатает тот же текст, поэтому расхождение между админкой и боем исключено.

`MemoryPromptBuilder` остаётся, но заголовки берёт из настроек; `EmotionService` получает метод чтения без `ensureForPersona`, чтобы предпросмотр не писал в базу. Основной путь использует существующий метод с добивкой строк.

### 5. Длинный ответ дробится

`TextSplitter` — чистая функция: лимит 4000 символов (запас до 4096), приоритет границ `\n\n` → `\n` → `. ` → ` ` → жёсткий разрыв. `MessageSender.sendLongMessage` отправляет части по порядку; `AiService` сохраняет ответ в историю одной записью. Ошибка отправки части логируется и не отменяет остальные.

### 6. Админка: две новые страницы, меню из шести пунктов

«Промпт» (`/admin/prompt`) и «Эмоции» (`/admin/emotions`) — отдельные контроллеры по образцу `AdminPersonaController`, с той же проверкой пароля и тем же шаблоном меню. Предпросмотр — `GET /admin/prompt/preview?chatId=...`, вывод в `<pre>`.

`EmotionRepository` получает сохранение справочника и фраз с валидацией диапазонов на стороне формы: шкалы 0..10, вес -1..1, затухание ≥ 0, полоса `from <= to`.

### 7. Миграция

Одна идемпотентная миграция `010_prompt_constructor.sql`: колонки, бэкфилл, настройки, блок прав `app_user` как в 003–009.

Бэкфилл — только для строк `content LIKE 'Сообщение от: %'`: ник и имя извлекаются регулярным выражением, префикс срезается. `author_user_id` подставляется, только если ник однозначно находится в `tg_users`; иначе остаётся `NULL` — старые сообщения доживут в окне 100 и уйдут.

## Risks / Trade-offs

- **Снятие префикса задевает анализ памяти** → рендер строки один и тот же для истории и анализа, плюс тест на совпадение формата.
- **Бэкфилл необратим для старых строк** → перед накатом снять дамп `ai_messages`; откат кода без дампа вернёт историю без авторов.
- **`AiServiceTest` мокает восемь зависимостей и проверяет три системных сообщения** → тесты переносятся на `PromptComposer` и `TextSplitter`, в `AiService` остаётся проверка оркестрации.
- **Предпросмотр может писать через `ensureForPersona`** → отдельный метод чтения без добивки.
- **Промпт растёт** → бюджеты и логирование длин; память по-прежнему топ-N, персона предупреждает при > 6000.
- **Дробление меняет число сообщений в чате** → только при превышении лимита; короткие ответы идут как раньше.
- **PII в шаблонах** → заготовки в миграции нейтральные, реальные значения — на сервере; предпросмотр доступен только через loopback и пароль.
- **Две новые страницы в меню** → обновить тест навигации админки.

## Migration Plan

1. Снять дамп `ai_messages` (вне репозитория).
2. Накатить `010_prompt_constructor.sql` на прод от владельца схемы.
3. Собрать jar, локально проверить старт и один ответ в чате.
4. Пуш в `main` → деплой перезапускает бота.
5. Вручную: убрать техническую часть из `personas.prompt` и синхронизировать `openspec/brief/yura-persona.md`.
6. Смоук в реальном чате: обращение по имени, ответ на длинный вопрос, предпросмотр промпта в админке.
