# Design

## Context

Формула затухания живёт в `MemoryDecay` и считается при чтении. Пол был константой 1; теперь это настройка, которую читают и `MemoryPromptBuilder` (печать важности), и `PromptComposer` (ранжирование пула).

## Approach

1. `MemoryDecay.minImportance()` читает настройку, проверяет диапазон 1..10 и возвращает 1 при пустом или некорректном значении.
2. Формула: `max(min(порог, база), база − дни / дней_на_балл)`. Внутренний `min` не даёт порогу поднять важность выше базовой.
3. `PromptComposer.memoryPool` читает скорость и порог один раз и передаёт их в ранжирование; `MemoryPromptBuilder` вызывает `effective(memory)`, который читает оба значения сам.

## Decisions

- **Одна настройка на все события, без порога по категориям.** Стареют только события; отдельные пороги для них не нужны.
- **Диапазон 1..10.** Ноль как «без пола» не нужен: затухание выключается нулевой скоростью, а не нулевым порогом.
- **Порог не поднимает важность.** Иначе низкая оценка записи перебивалась бы настройкой и искажала ручную разметку.

## Risks

- При пороге выше базовой важности старых событий их порядок определяется датой, а не важностью — это ожидаемое поведение настройки.
- Без наката миграции настройка работает на значении 1, то есть как раньше, но без описания в админке.
