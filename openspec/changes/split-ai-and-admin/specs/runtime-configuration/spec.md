# Spec Delta

## MODIFIED Requirements

### Requirement: Подключение к PostgreSQL через пул соединений

Система SHALL подключаться к одной базе PostgreSQL разными ролями: AI-бот — `ai_user`, админка — `admin_user`, а каждая роль MUST иметь доступ только к своим схемам и к общей схеме `shared`.

#### Scenario: Успешное подключение к базе данных

- **WHEN** приложение запускается с корректными параметрами подключения и своей ролью
- **THEN** пул соединений инициализируется, и приложение выполняет запросы к разрешённым схемам

#### Scenario: Обращение к чужой схеме

- **WHEN** AI-бот пытается прочитать таблицу из схемы `fun`
- **THEN** база отклоняет запрос с ошибкой прав, и бот не получает данные

#### Scenario: Недоступная база данных

- **WHEN** база данных недоступна по указанному URL
- **THEN** приложение логирует ошибку подключения и не начинает обработку сообщений

### Requirement: Воспроизводимая схема через SQL-миграции

Система SHALL предоставлять идемпотентные SQL-миграции, которые создают схемы `shared`, `config`, `ai` и `configurator` и все таблицы этих схем. DDL общей схемы `shared` и разовый перенос данных MUST храниться отдельным набором скриптов вне репозитория и MUST NOT выполняться при обычном накате миграций приложения.

#### Scenario: Накат миграций на чистую базу данных

- **WHEN** скрипты `shared` и миграции приложения применяются к пустой базе данных через `psql`
- **THEN** создаются все схемы, таблицы и seed-данные, и приложения работают без ошибок

#### Scenario: Повторный накат миграций

- **WHEN** миграции применяются повторно к уже созданной схеме
- **THEN** выполнение не вызывает ошибок и не дублирует существующие данные

#### Scenario: Перенос данных из public

- **WHEN** выполняется разовый перенос таблиц из `public` в новые схемы
- **THEN** количество строк в каждой таблице совпадает с дампом до переноса, а в `public` не остаётся прикладных таблиц

### Requirement: Запуск с конфигурацией из переменных окружения

Система SHALL получать конфигурацию каждого приложения из его собственных переменных окружения. AI-бот MUST получать `BOT_TOKEN`, `BOT_DB_*` и ключи `BOT_AI_KEY_<ID>`; админка MUST получать свой `BOT_TOKEN`, `BOT_DB_*` и `BOT_ADMIN_PASSWORD`, `BOT_ADMIN_PORT`, `BOT_ADMIN_BIND` и MUST NOT получать ключи провайдеров. Оба приложения MUST NOT требовать файл конфигурации или позиционные аргументы командной строки.

#### Scenario: Запуск с полным набором переменных окружения

- **WHEN** AI-бот запускается с `BOT_TOKEN`, `BOT_DB_*` и ключом `BOT_AI_KEY_DEEPSEEK`
- **THEN** приложение использует переданные значения и запускает бота

#### Scenario: Запуск админки с полным набором переменных

- **WHEN** админка запускается со своим `BOT_TOKEN`, `BOT_DB_*` и `BOT_ADMIN_PASSWORD`
- **THEN** приложение поднимает админку и бота-уведомителя, не обращаясь к ключам провайдеров

#### Scenario: Отсутствует обязательная переменная

- **WHEN** у приложения не задана одна из его обязательных переменных `BOT_TOKEN`, `BOT_DB_URL`, `BOT_DB_USER`, `BOT_DB_PASSWORD`
- **THEN** это приложение завершается с ненулевым кодом и сообщением с именем переменной, не подключаясь к базе и Telegram

#### Scenario: Переменные админки не заданы

- **WHEN** AI-бот запускается без `BOT_ADMIN_PASSWORD`, `BOT_ADMIN_PORT` и `BOT_ADMIN_BIND`
- **THEN** бот запускается и работает как обычно, а админка в этом процессе не поднимается

#### Scenario: Ключа ИИ нет ни у одного провайдера

- **WHEN** AI-бот запускается без единой переменной `BOT_AI_KEY_<ID>`
- **THEN** он запускается, публикует статус «ключа нет» и обрабатывает сообщения, не требующие модели

#### Scenario: Конфигурация передана аргументами командной строки

- **WHEN** приложение запускается с позиционными аргументами вместо переменных окружения
- **THEN** аргументы не используются как конфигурация, а запуск завершается с ошибкой обязательных переменных

## ADDED Requirements

### Requirement: Изоляция схем по ролям

Система SHALL выдавать каждой роли только те права, которые нужны её приложению: `ai_user` работает со схемами `shared`, `config` и `ai`; `admin_user` — с `shared`, `config`, `ai` и `configurator`; `fun_user` — с `shared` и `fun`. Ни одна роль MUST NOT читать схемы другого приложения, кроме `shared`.

#### Scenario: Бот не читает игры

- **WHEN** роль `ai_user` выполняет запрос к таблице схемы `fun`
- **THEN** база возвращает ошибку прав доступа

#### Scenario: Админка не читает игры

- **WHEN** роль `admin_user` выполняет запрос к таблице схемы `fun`
- **THEN** база возвращает ошибку прав доступа

#### Scenario: Игры не читают конфигурацию и память

- **WHEN** роль `fun_user` выполняет запрос к таблице схем `config` или `ai`
- **THEN** база возвращает ошибку прав доступа

#### Scenario: Общие пользователи и чаты доступны всем

- **WHEN** любая из трёх ролей обновляет `shared.tg_users` или `shared.tg_chats`
- **THEN** запись сохраняется, и её видят остальные приложения
