# Spec Delta

## REMOVED Requirements

### Requirement: Алиасы не конфликтуют с командами и другими персонами

**Reason**: Уникальность алиаса между персонами больше не нужна: в чате привязана одна персона, поэтому одинаковое имя в разных чатах не создаёт неоднозначности. Ограничение оставалось только в проверке формы.

**Migration**: Одинаковый алиас можно указывать у нескольких персон. Внутри одной персоны уникальность сохраняется, а совпадение с командой бота по-прежнему запрещено.

## ADDED Requirements

### Requirement: Алиасы не конфликтуют с командами бота

Система SHALL принимать алиас только как одно слово без пробелов и знаков препинания и MUST отклонять алиас, совпадающий с командой бота. Одинаковый алиас у разных персон MUST приниматься: обращение разрешается по чату, а у чата одна персона.

#### Scenario: Алиас совпадает с командой

- **WHEN** администратор указал алиас `clear` или `summary`
- **THEN** форма возвращается с ошибкой, называющей конфликтующую команду

#### Scenario: Одинаковый алиас у двух персон

- **WHEN** администратор указал персоне алиас, который уже есть у другой персоны, в том же или другом регистре
- **THEN** алиас сохраняется, и каждая персона откликается на него в своём чате

#### Scenario: Повтор алиаса внутри одной персоны

- **WHEN** в поле алиасов одной персоны одно и то же слово указано дважды
- **THEN** сохраняется одно значение, дубль отбрасывается

#### Scenario: Имя-обращение персоны

- **WHEN** администратор указал алиас `юра`
- **THEN** алиас принимается как обычный: команды с таким именем больше нет, а обращение идёт по алиасу персоны

#### Scenario: Алиас из нескольких слов

- **WHEN** администратор указал алиас с пробелом или знаком препинания
- **THEN** форма возвращается с ошибкой о формате алиаса
