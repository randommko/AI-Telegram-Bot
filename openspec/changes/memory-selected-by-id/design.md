# Design

## Context

`AnswerPlanner` получает каталог «ядро + топ-N» и возвращает `memory_ids`. `PromptComposer.memories()` повторно берёт «ядро + топ-N» и фильтрует его по этим id. Любой id за пределами топ-N отбрасывается молча: список выбранного не содержит запись, а если не совпало ничего — подставляется весь топ-N.

## Approach

1. `MemoryRepository.findByIds(int personaId, Collection<Integer> ids)` — тот же селект, что у `findByPersona`, но с условием `m.id = ANY (?)`; пустой список возвращает пустой результат без запроса.
2. `PromptComposer.memories()`:
   - ids пуст → прежний путь (ядро + топ-N);
   - ids непуст → `findByIds`; если вернулось пусто → прежний фолбэк на топ-N и WARN с числом отброшенных id;
   - если вернулось непусто → ядро + найденные записи, WARN на разницу между запрошенным и найденным.
3. Ядро прикладывается всегда и не зависит от выбора.

## Decisions

- **Не расширять выборку топ-N до всей памяти и фильтровать в Java.** Лишние строки и агрегация людей на каждый ответ; выборка по id дешевле и точнее.
- **Не падать на неизвестный id.** План может вернуть устаревший или чужой идентификатор; ответ важнее строгости. Один WARN с количеством, без строки на каждый id.
- **Фолбэк сохраняется.** Пустой выбор — это не ошибка, а сигнал «план не выбрал»; прежнее поведение оставляем, чтобы не оставить генерацию без памяти.

## Risks

- План начнёт возвращать много несуществующих id → WARN в каждом ответе. Лечится текстом инструкции плана, отдельной задачей.
- Выборка по id без индекса: `id` — первичный ключ, дополнительный индекс не нужен.
