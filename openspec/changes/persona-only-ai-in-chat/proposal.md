# Proposal

## Why

В чате с привязанной персоной `/ai` работает так же, как обращение по имени: промпт всё равно берётся из персоны. Из-за этого у персоны два входа — имя и служебная команда, — и участнику не нужно обращаться к персонажу, чтобы получить его ответ. Команда существует для чатов без персоны, где другого способа позвать AI нет.

Отдельная проблема — имена `/юра`, `/юрий`, `/юрец` зашиты в `Command.AI` для одной конкретной персоны. Из-за них в `AdminPersonaValidator` появилось исключение `PERSONA_ADDRESS_NAMES`, а в чате с другой персоной `/юра` отвечает её голосом. После того как имена персон живут в `persona_aliases`, эти три написания ничего не добавляют.

## What Changes

- **`/ai`, `/ии`, `/аи` работают только в чате без персоны.** Если у чата есть персона, бот не обращается к AI, а отвечает одной подсказкой с именем персоны: «В этом чате отвечает Юра. Напиши вопрос с обращением — например: «Юра, как дела?»». В чате без персоны поведение прежнее.
- **BREAKING** — `/юра`, `/юрий`, `/юрец` удаляются из `Command.AI`. Слэш-обращения по имени больше нет: `/юра вопрос` становится неизвестной командой, бот молчит, а текст после слэша остаётся в истории — как у любой неизвестной команды.
- **Обращение по имени остаётся только через алиасы персоны** (без слэша). В базе ничего не меняется: персоны, у которых `юра`/`юрий`/`юрец` уже в `persona_aliases`, продолжают откликаться на эти слова в тексте.
- **Админка упрощается:** исключение для имён-обращений (`PERSONA_ADDRESS_NAMES`) удаляется, эти алиасы принимаются как обычные — команды с такими именами больше нет.
- **Подсказка отправляется и на `/ai` без вопроса:** в чате с персоной правило про персону важнее сообщения «Напиши свой вопрос после команды /ai».
- **Спеки и README приводятся в соответствие:** из `ai-invocation` уходит «в любом чате», из `persona` — «слэш-команды доступны в любом чате» и сценарий про алиас-синоним команды AI.
- `/clear` и `/bot_info` не меняются.

## Capabilities

### New Capabilities

Нет: правило входа в AI уже описано возможностями `ai-invocation` и `persona`.

### Modified Capabilities

- `ai-invocation`: требование «Запрос к AI по слэш-команде» сокращается до трёх команд и ограничивается чатом без персоны; удаляется сценарий «Любой чат» и упоминание `/юра`, `/юрий`, `/юрец`; добавляются сценарии подсказки в чате с персоной и молчания на `/юра`.
- `persona`: в требовании «Чат без персоны сохраняет прежнее поведение» слэш-команды ограничиваются чатом без персоны; из требования про алиасы убирается фраза об именах-обращениях и сценарий «Имя-обращение персоны»; сценарий «Удалённый алиас» перестаёт утверждать, что слэш-команды продолжают работать.

## Impact

- `core/src/main/java/org/example/core/Command.java` — `AI("/ai", "/ии", "/аи")`, три имени удаляются.
- `bot/src/main/java/org/example/bot/CommandDispatcher.java` — `handleAi` проверяет `personaForChat(chatId)`: персона есть → подсказка с её именем и запись в лог, иначе `askAi` как сейчас.
- `admin/src/main/java/org/example/admin/AdminPersonaValidator.java` — удаляются `PERSONA_ADDRESS_NAMES` и исключение в `forbiddenCommands()`.
- `bot/src/test/java/org/example/bot/CommandDispatcherTest.java` — `slashCommandStillWorksAsBefore` сейчас вызывает `/юра`; добавляются проверки подсказки в чате с персоной и молчания на `/юра`.
- `admin/src/test/java/org/example/admin/AdminPersonaValidatorTest.java` — кейс «алиас `юра` разрешён как синоним AI» проверяет приём алиаса уже без исключения.
- `README.md` — строка про слэш-команды «в любом чате», список разрешённых имён-обращений в проверках карточки персоны.
- База, миграции, конфиг и деплой не меняются. Риск раскатки: у привычки писать `/юра` ответа больше не будет — ошибки нет, бот просто молчит, поэтому в отчёте о выкатке об этом стоит сказать.
