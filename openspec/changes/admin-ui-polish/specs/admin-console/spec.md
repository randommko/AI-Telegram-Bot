# Spec Delta

## ADDED Requirements

### Requirement: Чаты обозначаются названием

Система SHALL показывать чат в интерфейсе админки его названием и MUST использовать числовой идентификатор только тогда, когда названия нет.

#### Scenario: Список персон

- **WHEN** у персоны есть привязанный чат с названием
- **THEN** в столбце «Чаты» видно название чата, а не его идентификатор

#### Scenario: Строка модератора

- **WHEN** владелец открыл раздел «Модераторы»
- **THEN** в списке выданных чатов и в списке выдачи видны названия, а не идентификаторы

#### Scenario: Чат без названия

- **WHEN** у чата нет названия
- **THEN** показывается его числовой идентификатор как запасной вариант

## MODIFIED Requirements

### Requirement: Подсказки к полям берутся из базы

Система SHALL показывать рядом с настраиваемым полем иконку с описанием и MUST брать текст из базы: `bot_settings.description` для настроек, `emotions.description` для эмоций персоны и `persona_field_notes` для параметров персоны. Если описания нет, иконка MUST NOT выводиться. Исключение — поля «Вес в агрессию», «Затухание в час» и «Базовое значение» раздела «Эмоции»: их подсказки описывают смысл параметра, а не конкретную эмоцию, и MAY быть заданы в интерфейсе.

#### Scenario: Описание у эмоции

- **WHEN** администратор открывает вкладку «Эмоции» карточки персоны
- **THEN** у каждого поля эмоции есть иконка с текстом из описания этой эмоции

#### Scenario: Описание у настройки

- **WHEN** администратор открывает вкладку «Модель»
- **THEN** у температуры есть иконка с текстом из описания этой настройки в базе

#### Scenario: Описание отсутствует

- **WHEN** у поля нет описания в базе
- **THEN** иконка у этого поля не выводится

#### Scenario: Правка описания в базе

- **WHEN** описание поля изменено в базе
- **THEN** следующий открытый раздел показывает новый текст без перезапуска бота

#### Scenario: Фиксированные подсказки справочника эмоций

- **WHEN** администратор открыл вкладку эмоции в разделе «Эмоции»
- **THEN** у веса, затухания и базового значения есть иконки с пояснением смысла параметра, одинаковым для всех эмоций

### Requirement: Раздел настроек объясняет добавление ключей

Система SHALL показывать на вкладке «Модель» инструкцию по ключам провайдеров: где взять ключ, что деплой пересобирает `bot.env` из секретов репозитория, команды ручного добавления на сервере и таблицу переменных `BOT_AI_KEY_<ID>` с поставщиком, открываемыми моделями и пометкой о наличии ключа. Пометка MUST браться из `ai.provider_key_status`, а таблица — из каталога провайдеров. На остальных вкладках настроек инструкции MUST NOT быть.

#### Scenario: Таблица покрывает весь каталог

- **WHEN** администратор открывает вкладку «Модель»
- **THEN** в таблице есть строка для каждого провайдера каталога со своей переменной `BOT_AI_KEY_<ID>`

#### Scenario: Ключ есть и ключа нет

- **WHEN** в `ai.provider_key_status` у части провайдеров записано наличие ключа
- **THEN** в строке такого провайдера стоит пометка «есть», а у остальных — «нет»

#### Scenario: Новый провайдер в каталоге

- **WHEN** в каталог добавлен провайдер
- **THEN** его строка появляется в таблице без правки шаблона страницы

#### Scenario: Сводка ключей видна до раскрытия инструкции

- **WHEN** администратор открывает вкладку «Модель»
- **THEN** над формой есть строка со всеми поставщиками и пометкой «есть» или «нет» у каждого

#### Scenario: Метка ключа окрашена

- **WHEN** у провайдера ключ есть, а у другого нет
- **THEN** метка с ключом показана зелёной, а метка без ключа — красной

#### Scenario: Чужие вкладки без ключей

- **WHEN** администратор открывает вкладку «Память», «Промты» или «Уведомления»
- **THEN** блоков текущей модели, ключей и инструкции на странице нет

### Requirement: Настройки показывают текущую модель

Система SHALL показывать на вкладке «Модель» отдельным блоком модель, которой бот отвечает сейчас, её поставщика и способ подключения — прямое или через агрегатор. Если сохранённой пары нет в каталоге, блок MUST вместо поставщика показывать предупреждение и модель по умолчанию, которой бот ответит. На остальных вкладках блока MUST NOT быть.

#### Scenario: Прямое подключение

- **WHEN** сохранена модель прямого провайдера
- **THEN** блок показывает идентификатор модели, поставщика и «прямое подключение»

#### Scenario: Подключение через агрегатор

- **WHEN** сохранена модель агрегатора
- **THEN** блок показывает идентификатор, поставщика и «через агрегатор»

#### Scenario: Пара не найдена

- **WHEN** в настройках значение, которого нет в каталоге
- **THEN** блок показывает это значение и предупреждение, что бот ответит моделью по умолчанию

#### Scenario: Другая вкладка

- **WHEN** администратор открывает вкладку «Уведомления»
- **THEN** блока текущей модели на странице нет
