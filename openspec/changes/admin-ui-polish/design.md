# Design

## Context

См. `proposal.md` — Why. Что задаёт форму решения:

- `settings.html` выводит блок текущей модели, сводку ключей и инструкцию до навигации вкладок, поэтому они остаются на странице при любой вкладке; поля вкладки рендерятся в `section` с `th:if="${tab.active}"`.
- `emotions.html` использует общий стиль `.field textarea { min-height: 120px }` для пяти фраз каждой эмоции.
- `moderators.html` на каждую учётку показывает отдельные формы «Выдать чат», «Выдать персону», «Сменить пароль» и «Удалить»; столбец «Чаты» печатает `account.chatIds`.
- `AdminAccountsController` уже отдаёт в шаблон `chats` (все чаты с названиями) и `personas` (все персоны), а строки доступа считает `ModeratorPersonaRepository.accessOf`.

## Goals / Non-Goals

**Goals:**

- Блоки модели и ключей видны только на вкладке «Модель».
- Поля фраз эмоций занимают две строки, у трёх параметров есть подсказки.
- В «Модераторах» чаты названы, а выдача чатов и персон сохраняется одной кнопкой на строку.
- Форма входа выровнена по центру.

**Non-Goals:**

- Изменение правил выдачи и отзыва доступа, состава источников и прав.
- Вкладка памяти (`persona-memory-tab`), миграции, изменения бота.

## Decisions

### D1. Блоки модели переезжают внутрь активной секции

Разметка «Текущая модель», «Ключи провайдеров» и инструкции переносится в `section` вкладки и оборачивается условием `th:if="${tab.id == 'model'}"`. Данные `currentModel` и `keyHints` контроллер отдаёт всегда — они нужны только этой ветке.

Альтернатива «скрывать блоки стилем на чужих вкладках» оставляет их в разметке и в тестах страницы; альтернатива «отдельная страница про модель» дробит настройки.

### D2. Флажок рисуется одной строкой с подписью

Для `kind == 'checkbox'` шаблон не выводит отдельный `<label>` сверху, а рендерит `<label class="checkbox-line">` с галочкой и подписью поля. Скрытое поле `false` остаётся после галочки — иначе снятый флажок сохранялся бы пустой строкой.

### D3. Фразы эмоций — две строки

У `textarea` фраз появляется класс с ограничением высоты (`min-height: 0; height: 3.2em;`) и `rows="2"`. Общий стиль `.field textarea` не меняется, чтобы не укоротить промпт персоны и промпт анализа.

### D4. Подсказки справочника — фиксированный текст

Три подсказки («вес — вклад эмоции в уровень агрессии», «затухание — насколько быстро эмоция возвращается к базовому значению», «базовое значение — к чему эмоция возвращается со временем») лежат в шаблоне.

Альтернатива «завести таблицу заметок справочника» требует миграции и формы правки, которых в задаче нет. Спека `admin-console` уточняется: подсказки из базы остаются для настроек, эмоций персоны и параметров персоны, а три подсказки справочника — исключение.

### D5. Строка модератора — одна форма в ячейке действий

Форма строки живёт целиком в последней ячейке: два `<details>` с галочками (чаты и персоны) и одна кнопка «Сохранить». Столбцы «Чаты» и «Персоны» показывают текущее состояние подписями. Вложенных форм нет, атрибут `form` на поля из разных ячеек не нужен.

Смена пароля и «Удалить» остаются отдельными формами в той же ячейке: это другие действия с другим подтверждением.

### D6. Сохранение строки считает разницу

`POST /admin/moderators/{id}/access` принимает `chatIds` и `personaIds` — полные наборы отмеченного. Контроллер сравнивает их с текущими: недостающие выдаёт, лишние отзывает. Оба набора проверяются: чат должен быть известен боту, персона — существовать и не быть доступной только по авторству или через чат.

Альтернатива «галочка применяется сразу» даёт запрос на каждый клик и не даёт отменить пачку изменений перед сохранением.

### D7. Все персоны, галочка только у выдачи

Список персон строится из всех персон каталога, а источник берётся из `accessOf`: «создал», «выдан», «через чат». Первые два источника, кроме «выдан», выводятся подписью без галочки; «выдан» и отсутствие доступа — галочкой.

Особый случай: если у персоны есть и выдача, и доступ через чат, `accessOf` вернёт «выдан» (приоритет источника в SQL). Снятие галочки отзовёт выдачу, но просмотр через чат останется — после перезагрузки строка покажет «через чат». Это ожидаемое поведение, а не ошибка.

### D8. Названия чатов — карта в модели

`AdminAccountsController` добавляет `chatTitles` — карту «идентификатор → название» из уже загруженного `findAllChats`. Шаблон печатает название, при его отсутствии — идентификатор. Отдельный запрос в базу не нужен.

### D9. Вход по центру

`main` на странице входа получает класс, заголовок выравнивается по центру, а `form.login` — `margin: 0 auto`. Ширина формы остаётся 320px.

## Risks / Trade-offs

- **Список персон в строке длинный** → выпадающий список получает ограничение высоты и прокрутку; строка таблицы не растягивается.
- **Отзыв выдачи, которая дублируется чатом, выглядит как «ничего не изменилось»** → это описано в D7; подпись «через чат» после сохранения объясняет, почему доступ остался.
- **Сохранение строки без изменений** → контроллер отвечает тем же сообщением «Доступы сохранены»; отдельная ветка «изменений нет» не нужна.
- **Фиксированные подсказки противоречат прежней формулировке спеки** → дельта `admin-console` явно называет их исключением.
- **Перенос блоков модели ломает тесты, которые искали их на любой вкладке** → тесты обновляются вместе с шаблоном в той же группе задач.

## Migration Plan

Схема базы не меняется. Деплой затрагивает `admin/**`, поэтому запускается только `Deploy admin`; бот продолжает работать на прежней сборке. Откат — revert коммита.
