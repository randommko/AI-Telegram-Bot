# Архитектурные решения (ADR)

Здесь хранятся долговечные решения проекта: выбор библиотеки, схемы данных, отказ от возможности, разделение приложений. Рядовые правки и детали реализации сюда не попадают — для них есть изменения OpenSpec.

## Когда заводить ADR

- Решение меняет структуру проекта или внешние зависимости.
- Решение отменяет прежнее поведение или возможность.
- Решение дорого переиграть позже (схема данных, транспорт, формат обмена).
- Выбор делался между вариантами, и причина отказа важна будущему читателю.

Не заводите ADR на одну правку в рамках уже принятого решения — это делает изменение OpenSpec.

## Правила

1. Один ADR — одно решение. Два независимых решения — два файла.
2. Имя файла: `NNNN-kebab-title.md`, номер по порядку, начиная с `0001`.
3. Шаблон — `ADR-TEMPLATE.md`, стиль зафиксирован в `openspec/preferences.md`.
4. Принятый ADR не редактируется. Замена оформляется новым ADR, а у старого в поле «Статус» пишется `Заменено на ADR-NNNN`.
5. Рядом с ADR кладётся ссылка на глоссарий: `<имя>-glossary-reference.md`. Определения в неё не копируются.
6. Факты не выдумываются: неизвестное помечается как `Неизвестно` или выносится в открытый вопрос.

## Статусы

| Статус | Значение |
| --- | --- |
| Предложено | Решение обсуждается, ещё не принято. |
| Принято | Решение действует. |
| Заменено на ADR-NNNN | Решение отменено более поздним, ссылка обязательна. |
