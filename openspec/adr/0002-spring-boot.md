# ADR-0002: Переход на Spring Boot

- **Статус:** Принято
- **Дата:** 2026-11-02
- **Затрагивает:** `application-bootstrap`, `runtime-configuration`

## Контекст

Приложение собиралось вручную: `Main` читал конфигурацию статическими методами, `TelegramBot` создавал девять сервисов и репозиториев через `new` прямо в полях, пул соединений поднимался в статическом поле, а проверка параметров сводилась к «не пусто» и `System.exit(1)`.

Из-за этого состав приложения нельзя было подменить в тесте, а опечатка в конфигурации обнаруживалась только после подключения к базе. Одновременно **деплой** и юнит уже были завязаны на фиксированный путь jar и переменные `BOT_*`, поэтому менять инфраструктуру не требовалось.

## Рассмотренные варианты

- **Оставить ручную сборку:** минимум правок и никаких новых зависимостей, но связность и поздняя валидация сохраняются. Не выбран — задача была именно убрать ручное связывание.
- **Spring Boot 3.x:** `@ConfigurationProperties` + `@Validated`, бины вместо `new`, `DataSource` из свойств, `SmartLifecycle` для регистрации в Telegram, `repackage` вместо shade. Выбран.
- **Spring без Boot:** контейнер даёт внедрение, но настройку `DataSource`, версии библиотек и сборку исполняемого архива пришлось бы делать руками — выигрыша перед Boot нет.
- **Другой DI-фреймворк:** пришлось бы отдельно решать сборку и жизненный цикл, а экосистема проверки конфигурации отсутствует.

## Решение

Приложение переводится на Spring Boot 3.x. Конфигурация читается только из переменных окружения `BOT_*` через валидируемый бин свойств; невалидные значения останавливают запуск до подключения к базе и Telegram. Регистрация бота с тремя попытками переезжает в `SmartLifecycle`, остановка вызывает `BotSession.stop()` с ограничением по времени. Сборка — `spring-boot-maven-plugin`, имя и путь jar не меняются.

## Последствия

- **Плюсы:** зависимости внедряются через конструктор и подменяются в тестах; ошибка конфигурации видна до сетевых подключений; версии библиотек приходят из BOM; **деплой** и юнит правок не потребовали.
- **Минусы:** позиционные аргументы командной строки перестали работать — это осознанное ломающее изменение; неверный env-файл при `Restart=always` даёт цикл рестартов, лимит сознательно не вводился.
- **Дальше:** при добавлении групп настроек помнить, что имена переменных зафиксированы инфраструктурой, а **миграция** схемы остаётся ручным SQL-скриптом.
